# Старт сессии · Game Factory

Парный навык к `handover`. Тот пишет файлы в конце сессии, этот читает их в начале - и
**проверяет, что написанному можно верить**: STATE мог отстать от GitHub и прода между
сессиями (П-041 - план однажды строился на снимке двухсессионной давности).

Первая строка ответа - канарейка (правило кита), ходы считаются с 1.

## 1. Рабочая копия - та и свежая

```
git fetch origin
git status -sb                             # ветка dev, не позади origin/dev
git log --oneline origin/main..origin/dev  # что ещё не выложено на прод
```

Копия не на `dev` или позади `origin/dev` - сказать владельцу **до** чтения документов:
это копия `main` (только смотреть прод) или в ней старый STATE. Ничего не переключать и не
тянуть без "да".

## 2. Прочитать - строго это

1. `CLAUDE.md` (загружен сам) - правила проекта, инварианты, команды.
2. `docs/STATE.md` - снимок целиком (≤ 120 строк).
3. `docs/ROADMAP.md` - только раздел текущего этапа (`grep -n '^## ' docs/ROADMAP.md`).
4. Спецификация этапа из `docs/specs/` - только слайс, который берём, и "Ограничения".
5. `docs/PITFALLS.md` - заголовки разделов (`grep -n '^## '`), затем раздел по теме задачи.

**Не читать** `docs/CHANGELOG.md`, `docs/DECISIONS.md` целиком: это журналы. Нужен `D-NNN` или
`П-NNN` - `grep -n 'D-0NN\.' docs/DECISIONS.md` и окно в 10-20 строк.

## 3. Сверить с реальностью

На сервере, без Docker и root (П-036):

```
pnpm typecheck && pnpm test     # число - сравнить с "Хэндовер" в STATE
free -m                         # test:db - только если доступно ≥ 2 ГБ (П-043)
gh run list --branch dev -L 3   # CI на последнем пуше
curl -s -o /dev/null -w '%{http_code}\n' https://games.youranus.ru/healthz   # 200 = база жива
```

Расхождение с STATE (число тестов, красный CI, 503 у `/healthz`) - **первая находка**, о ней
сказать до плана. Чего агент не видит сам (`docker ps`, журнал `gf-update`) - "со слов
владельца" или блок команд ему, а не "проверено" из прошлого STATE.

## 4. Выдать блок "Старт"

```
Этап N - <название>, слайс X.Y (<статус по ROADMAP>).
Следующий шаг: <одно действие из STATE>.
Блокеры и расхождения: <список или "нет">.
```

Затем план сессии в 2-4 пункта. Открытые вопросы к владельцу из STATE, которые касаются
задачи, - задать **до** работы.

## Помнить всю сессию

- Изменяющее на сервере и всё с Docker - только блоком владельцу (машина, пользователь,
  оболочка; откат - отдельным блоком). Коммит - с "да", пуш - блоком владельцу (правила кита).
- Сборка хаба и e2e - только CI: модуль, который импортирует хаб, может пройти юнит и упасть
  в `next build` (П-045).
- Правка play-server, моста, SDK, `deploy/`, авторизации - роль "Безопасность"
  (`CLAUDE.md`); модель сабагента сверять по журналу запуска (П-042).
- Репозиторий публичный: о сервере - только то, что разрешает D-043; тест
  `tools/public-repo.test.ts` ловит адреса и пути, остальное - глазами по списку D-043.
- Хук типографики меняет тире и кавычки на `-` и `"` - не спорить и не обходить (правило кита).
