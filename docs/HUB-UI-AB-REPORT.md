## Замер первого экрана

Chromium, CSS viewport 390×844, touch, масштаб 100%, загруженные шрифты и обложки,
верх документа. Гость и образец владельца дали одинаковые значения:

| Параметр | А, 2 строки | Б, 3 строки |
|---|---:|---:|
| Шапка | 64 px | 120 px |
| Начало первой карточки | 168 px | 264 px |
| Высота первой карточки | 405,375 px | 435,375 px |
| Нижняя граница первой карточки | 573,375 px | 699,375 px |
| Начало второй карточки | 585,375 px | 711,375 px |
| Нижняя граница второй обложки | 791,75 px | 917,75 px |
| Нижняя граница названия второй карточки | 821,75 px | 951,75 px |

А сохраняет полную вторую обложку и название, запас под названием 22,25 px.
Б показывает первую карточку целиком и 118,625 px второй обложки из 192,375 px
(примерно 62%). Дальше доступна обычная прокрутка.

Цена А: в мобильной шапке остаётся значок без слова Game Factory; все переходы
сохранены, выход владельца обозначен значком с доступным названием. «Каталог»
и «Игры» стоят в одной строке, заголовок 24 px вместо 30 px; вступление 15/22 px
вместо 16/24 px; описание 14/20 px ограничено двумя строками вместо трёх.
Внутренние отступы и промежуток перед сеткой уменьшены. На многоколоночном ряду
действия выровнены; на телефоне карточки имеют естественную высоту.

В дополнительной пробе А с тремя строками первая карточка увеличивается ровно
на 20 px; низ второго названия — 841,75 px, запас лишь 2,25 px. Это достижимо
на данном опорном viewport с этими данными, но практически без резерва.

Обе версии: рамка обложки 16:9, `object-fit: contain`, высота карточки из контента;
описание не резервирует отсутствующие строки, название не обрезается.
Шрифт оболочки в прототипе зависит от ширины и пользовательского размера,
а не текущей высоты. Кнопки имеют настоящие прямоугольники минимум 48×48 CSS px,
тень сохраняется отдельно от их высоты. При 200% действия переходят в строки.
Б скрывает слово логотипа по фактической вместимости его контейнера.

## Телефон: ADB и сценарий

Команды на компьютере, где доступен localhost работающего превью:

```bash
adb devices
adb reverse tcp:35733 tcp:35733
```

Открыть А и Б по прямым ссылкам выше в отдельных вкладках Chrome телефона.
Для одного только каталога нужен порт 35733. Если открывать ещё просмотрщик
с исходной базой, понадобятся также `adb reverse tcp:4194 tcp:4194` и
`adb reverse tcp:34935 tcp:34935`. После перезапуска сервера порты снимков могут
измениться: текущие значения — в `http://127.0.0.1:4194/config.json`, поля
`after` и `references[0].url`. Forwarding одного порта просмотрщика недостаточен.
Обратное направление при USB — `adb reverse`, а не `adb forward`.

1. Масштаб 100%, клавиатура закрыта, адресная строка раскрыта; дождаться картинок.
   Сравнить состав первого экрана А/Б, сохранить снимок, записать модель и Chrome.
2. Пять раз прокрутить несколько карточек вниз/вверх, скрывая/возвращая панель.
   Проверить, что картинка и карточка под пальцем не меняют размер.
3. На k8s открыть «…», закрыть; повторить с `&owner=1` и проверить доступность
   всех переходов шапки. Затем повернуть телефон туда/обратно и повторить после reload.
4. Увеличить текст, проверить действия и теги. Это проверка компоновки образцов;
   скачивание/вход/игра в этом превью не являются настоящими.

Для записи viewport открыть вкладку через Chrome на компьютере
`chrome://inspect/#devices`, в Console выполнить:

```js
const p = document.createElement('div');
p.style.cssText = 'position:absolute;height:100svh;visibility:hidden;pointer-events:none';
document.body.append(p);
console.log({innerWidth, innerHeight, visualWidth: visualViewport.width,
  visualHeight: visualViewport.height, scale: visualViewport.scale,
  svh: p.getBoundingClientRect().height});
p.remove();
```
