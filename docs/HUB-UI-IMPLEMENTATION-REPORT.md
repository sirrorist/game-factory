# Хаб — перенос принятого дизайна в приложение

Дата: 2026-10-19. База: `e8fda15681ac6af16d6f2f80ed4ae875fe6ba30d`.
Владелец разрешил фактические пункты 2–5 после просмотра Figma и уточнений R2.
Кандидат подготовлен к выпуску по разрешению владельца в чате. Авторизация, роли,
экономика и исходники игр не менялись.

## Реализация

- Каталог: обложка 16:9 / `contain`, естественный заголовок, описание до 5 строк на ПК
  (от 1100 px), до 3 строк на планшете и телефоне,
  body `gap: 6px; padding: 8px 12px 8px`; Play 32 px плюс внешний бортик 3 px, Download 35 px,
  «…» 32×22 px. Это согласованные исключения из 48 px; тень не считается hit area.
- Одна колонка на телефоне до 440 px включительно; fluid-ширина сохранена по решению
  владельца. Две колонки с 640 px; три и обычная шапка с 1100 px. В touch 640–959 px
  сетка ограничена 36 rem. Полные теги укладываются внутрь строки, остальные — в диалоге.
- Root rem зависит только от ширины, сохраняя пользовательское увеличение.
  Каталог не читает visualViewport и не измеряет собственную высоту карточки.
  По последнему уточнению владельца ряд больше не растягивается по высоте окна:
  описанию выделены одинаковые 5/3 строки, до тегов 10 px при root 16.
  Измеритель начала сетки удалён. Два ряда ровно до нижнего края больше не являются
  критерием; при необходимости используется обычная прокрутка.
- Шапка: полный бренд; бургер в компактном профиле. На ПК разрыв между именем
  и выходом 8 px при root 16. Справа drawer `calc(100% - 70px)`, border 0,
  slide/fade в обе стороны; `.is-active` рисует фон самого пункта с padding/radius,
  `::after` свободен.
- Общая основа `Popup` / `PopupNotice`: вход/выход по умолчанию, отложенное закрытие,
  Escape/backdrop, фокус и возврат, scroll lock, reduced motion, быстрый повтор.
  Notice немодальный и имеет рамку. Потребители: меню, теги, уведомление passkey,
  живые примеры `/kit`. Правило записано в apps/hub/AGENTS.md и проверяется unit-тестом.
- Обычная область игры и короткие страницы используют svh; fullscreen остаётся
  по актуальному окну. Вход/аккаунт/пустые состояния/404/Kit сохранены.
  Верхний дубль названия игры может сильно сокращаться при 200%; полное название
  ниже iframe доступно обычной прокруткой, как предусмотрено планом.
  При 200% Kit переносит длинные кнопки/названия, повтор занимает отдельную строку,
  HUD-примеры перестраиваются; рекорд сохраняет место для анимации числа.

- Длинные touch PNG собираются из обычных viewport-кадров без resize: выявлено,

- Промежуточные кадры анимаций — управляемая середина настоящих CSS keyframes,

  Это не естественный кадр через фиксированные 65ms. Синтетический visualViewport
  также не выдаётся за физическое скрытие панели или pinch zoom.
- `next/`: настоящая production-сборка Next, реальные обложки/игра в iframe,

## Дополнение перед выпуском

Владелец после приёмки задал лимит описания 5 строк на ПК и 3 на остальных
размерах. Этот отдельный CSS-штрих выполнен без повторных тестов по его указанию;
штатная production-сборка Next через webpack прошла, локальный стенд перезапущен
и просмотрен владельцем. Таблицы геометрии и хеши выше относятся к предыдущему
полному UI-прогону, а не выдают его за повтор после изменения лимита.
Длинные описания увеличивают естественный минимум карточки; на низком окне
это может требовать прокрутки второго ряда. Выпуск разрешён владельцем:
«кайф, давай запушим в прод». Удалённые CI и Publish будут проверены при выпуске.

### Уточнение высоты карточек

После коммита `7c56d4d` владелец отменил растяжение рядов по окну и требование
попадать двумя рядами ровно в нижний край. `grid-auto-rows` и клиентские измерения
удалены. Высота описания — 5 × 1.25 rem на ПК и 3 × 1.25 rem ниже 1100 px;
до тегов 0.625 rem (10 px при root 16), включая gap. Короткое описание сохраняет
область под те же строки. Текст 200% увеличивает её вместе со шрифтом.

Адресная проверка настоящего Next: webpack build прошёл; smoke на 8 размерах
подтвердил неизменность карточек при увеличении **высоты** окна на 240 px,
стабильность visualViewport, лимит 3/5 и меню. 16 снимков/замеров двух тем,
включая 314/440 px, landscape, Full HD/QHD/4K и текст 200%, сохранены отдельно:
`test-results/ui/hub/runs/catalog-content-height-20261019/report.json`.
Высота обычной карточки при 1920 px — 414 CSS px, при 314 px — 352.625 CSS px.
Старые базы и полный исторический прогон сохранены; физический телефон повторно
не проверен. CI больше не требует растягивать карточки до нижнего края.

## Проверка телефона владельцем

Настоящий хаб: **http://localhost:3012/**; игра: **http://localhost:3012/games/snake**.
Стенд слушает loopback; сервер игр — 3013. Открывать top-level страницу.

```bash
adb devices
adb reverse tcp:3012 tcp:3012
adb reverse tcp:3013 tcp:3013
```

Если стенд остановлен, при готовой сборке Next:

```bash
node tests/ui/targets/hub/device-stand.ts --data /tmp/gf-e2e-AninPb --hub-port 3012 --play-port 3013
```

1. Открыть localhost:3012; записать устройство, браузер, CSS innerWidth/innerHeight,
   visualViewport.height/scale. Масштаб 100%, клавиатура закрыта, обложки загружены.
2. Прокрутить вниз/вверх, скрывая и возвращая панель: размер/состав карточки не скачет.
3. Меню: вход и выход с fade/slide, все пункты доступны; окно тегов закрывается плавно.
4. Повернуть телефон; теги и действия остаются внутри карточки. Проверить текст 200%.
5. Открыть snake; ready, поворот, fullscreen/выход при поддержке; вернуться в каталог.
6. Вход и настоящую экранную клавиатуру проверять отдельно на стенде с тестовой БД.
   Если play.localhost/поддомены не разрешаются на телефоне, записать это как сбой
   подключения; не ослаблять origin/sandbox ради обхода.

## Непроверенное и границы

Физический Android/Chrome, Safari/iPhone, настоящая экранная клавиатура и pinch zoom
ещё не проверены. GF_E2E_PG не задан: реальный auth/PostgreSQL e2e не запускался;
внешний вид owner/account/Kit проверен образцами, серверные ограничения — существующим
guest-e2e. Удалённый CI не запускался: нет разрешения на push/публикацию.
Figma доступна по сохранённой ссылке из плана; последние R2-поправки в сам файл не
записаны из-за лимита интеграции. Локальные снимки текущего кода доступны для ручной сверки.

После доступных проверок остаётся приёмка владельцем на устройстве. Этап 2А не начат.
