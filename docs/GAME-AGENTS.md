# Разработка игр агентами - локальные сессии

> Для владельца, который запускает агентов (Claude Code, Codex / ChatGPT, Gemini CLI и других)
> **на своей машине**, и для самих агентов. Написан без привязки к модели; чем агенты различаются -
> таблица в разделе 2. Сессия на VPS-1 живёт по `CLAUDE.md` и навыкам `session-start` / `handover`;
> локальная игровая сессия - по этому документу и [`../games/AGENTS.md`](../games/AGENTS.md) (D-059).
> Справочник по играм (манифест, toolchain, офлайн) - [GAMES.md](GAMES.md), API SDK - [SDK.md](SDK.md).

## Принцип в трёх строках

1. **Одна сессия - одна игра - одна папка `games/<id>/`.** Всё, что вне неё, агент не трогает.
2. **Готово - значит прошли команды**, а не "агент сказал готово" (раздел "Готово").
3. **Память - в файлах, не в чате**: бриф, решения и состояние игры лежат в `games/<id>/NOTES.md`,
   и новая сессия поднимает контекст оттуда.

## 1. Подготовить машину (один раз)

Нужно: Node ≥ 22.18 (`.nvmrc`), pnpm 10 (`corepack enable`), git. Windows - через WSL.

```bash
# машина владельца · ваш пользователь · bash или zsh
git clone https://github.com/sirrorist/game-factory.git gf
cd gf
git switch dev
pnpm install
pnpm exec playwright install chromium   # для e2e
pnpm typecheck && pnpm test             # ожидаемо: всё зелёное
```

Число тестов на сегодня - в [STATE.md](STATE.md), раздел "Хэндовер". Красное на чистой копии -
не начинать игру, а сказать в сессию на VPS-1: копия или машина не та.

## 2. Отдельная копия на каждую игру

Несколько агентов в одной рабочей копии мешают друг другу: один собирает, другой правит
`package.json`, третий откатывает чужое. Поэтому **у каждого агента - свой git worktree** и своя
ветка `game/<id>` от свежего `dev` (D-059). Ветку создаёт владелец, не агент (D-042).

```bash
# машина владельца · ваш пользователь · bash или zsh · из папки gf
git fetch origin
git worktree add ../gf-my-game -b game/my-game origin/dev
cd ../gf-my-game
pnpm install
```

Агент запускается **в этой папке**. Что он прочитает сам:

| Агент | Файл правил | Как попадает `games/AGENTS.md` |
|---|---|---|
| Claude Code | `CLAUDE.md` | `games/CLAUDE.md` подключает его при работе в `games/` |
| Gemini CLI | `GEMINI.md` | `games/GEMINI.md` подключает его (`@AGENTS.md`) |
| Codex (ChatGPT), Cursor и другие | `AGENTS.md` | корневой `AGENTS.md` велит прочитать; надёжнее - первой фразой задачи |
| Чат без доступа к файлам | - | вставить `games/AGENTS.md` и бриф в начало разговора |

Первая фраза задачи любому агенту: "Прочитай `games/AGENTS.md` и `docs/GAME-AGENTS.md`, затем
`games/<id>/NOTES.md`, если он есть". Убрать копию, когда ветка влита:

```bash
# машина владельца · ваш пользователь · bash или zsh · из папки gf
git worktree remove ../gf-my-game
git branch -d game/my-game
```

## 3. Поставить задачу - бриф

Самое дорогое в работе агента - угадывание. Бриф снимает его. Агент кладёт бриф первым разделом
`games/<id>/NOTES.md` (образец - раздел 7) и без брифа не начинает: нет критерия - нет задачи.

```markdown
## Бриф
- id: my-game                       # поддомен: a-z, 0-9, дефис, до 40 символов
- Жанр и суть в одной фразе: ...
- Движок: Phaser / Three.js / без движка (static)
- Управление: клавиатура / мышь / тач - что обязательно
- Очки: за что начисляются, что считается рекордом
- Сохранения: что сохраняем (или "нет")
- Права манифеста: saves, leaderboard, fullscreen, ... (GAMES.md, "Поля манифеста")
- Офлайн-архив: да / нет
- Вид: своя графика кодом / свои картинки импортом (без чужих ассетов и брендов)
- Первая версия - готово, когда: 3-5 проверяемых пунктов
- Вне первой версии: ...
```

Пункт "готово, когда" пишется так, чтобы его можно было проверить: "раунд кончается при
столкновении, рекорд виден в хабе после перезагрузки", а не "игра интересная".

## 4. Ход работы агента

Цикл - **разведать → план → маленький шаг → проверить → записать**, и так до готовности.

1. **Разведать.** Прочитать `games/AGENTS.md`, этот документ, GAMES.md, SDK.md и одну
   эталонную игру того же движка (таблица ниже). Код не писать.
2. **План** в 3-7 пунктов - в `NOTES.md` и владельцу. Ждать "да", если план меняет бриф.
3. **Шаг - одна функция игры за раз** (управление, затем столкновения, затем очки...). После каждого
   шага игра запускается и проверки зелёные; полуготовое не копится.
4. **Логику - отдельно от отрисовки**: правила, генерация, счёт - чистые функции в `src/` без DOM,
   на них - `games/<id>/test/*.test.ts` (`node:test`). Отрисовку проверяет e2e и глаз.
5. **Проверить как игрок**, а не только тестом: открыть в браузере, пройти раунд, глянуть консоль.
   Агенту с браузером - скриншот; без браузера - так и написать в отчёте ("не смотрел глазами").
6. **Записать** в `NOTES.md`: что сделано, чем проверено, что дальше. Контекст сессии кончится,
   файл останется.

Эталоны - копировать устройство, а не изобретать:

| Нужно | Смотреть |
|---|---|
| Игра без сборки | `games/snake` |
| 2D, Phaser 4, текстуры кодом, уровни сложности | `games/phaser-2d` |
| 3D, Three.js, полный экран | `games/three-3d` |
| Тяжёлая игра: чанки, захват мыши, большие сохранения, тач, юнит-тесты логики | `games/k8s-at-home` |
| Заготовка новой игры | `templates/vite-ts` (через `pnpm gf new <id>`) |

## 5. Команды

Игра на TypeScript + Vite (основной путь):

```bash
pnpm gf new my-game                          # копия шаблона в games/my-game
pnpm install
pnpm --filter @gf-game/my-game add phaser    # движок, если нужен
pnpm --filter @gf-game/my-game dev           # Vite, SDK в режиме standalone
```

Проверки одной игры - от быстрых к медленным (проверено на `k8s-at-home`, сессия №10):

```bash
pnpm gf validate my-game
pnpm --filter @gf-game/my-game typecheck
node --test "games/my-game/test/*.test.ts"   # если есть логика с тестами
pnpm games:build my-game --replace           # --replace - только на своей машине
pnpm games:export my-game                    # офлайн-архив; ошибки file:// - здесь
```

Посмотреть в хабе: `pnpm play` (игры, порт 4100) и `pnpm hub` (хаб, порт 3000) в двух терминалах,
затем `http://localhost:3000`. Хаб без базы открывается, вход владельца без базы не работает -
играм он не нужен (по коду `apps/hub/src/lib/db.ts`). Игра напрямую -
`http://my-game.play.localhost:4100/`, архив - распаковать и открыть `index.html` двойным кликом.

Полный прогон, как в CI: `pnpm check`. На своей машине его можно (D-049 ограничивает только
сервер), но e2e входа (`tests/e2e/auth.test.ts`) просят Postgres в `GF_E2E_PG`; без него -
только e2e игр (на сервере не гонялось - D-049; в CI зелёные):

```bash
pnpm games:build && pnpm games:export && pnpm hub:build
node --test --test-concurrency=1 tests/e2e/offline.test.ts tests/e2e/hub.test.ts
```

## 6. Готово - когда прошло всё

Агент сдаёт игру только с этим списком, у каждого пункта - команда и её итог:

- [ ] Пункты "готово, когда" из брифа - каждый проверен, и сказано чем.
- [ ] `pnpm gf validate`, `typecheck`, тесты игры, `games:build`, `games:export` - зелёные.
- [ ] `pnpm typecheck && pnpm test` всего репозитория - зелёные (игра не сломала общее).
- [ ] `ready()` вызывается, когда игра правда готова к вводу, а не сразу после `init` (SDK.md).
- [ ] Игра работает и в хабе, и сама по себе (`mode` - `hub` и `standalone`), и из архива
      через `file://`, если `offline: true`.
- [ ] Ни одного `fetch`/XHR за ассетами, ни top-level `await` (П-002, П-018, П-019).
- [ ] Права манифеста - только то, что игра правда использует.
- [ ] Тач работает, если в брифе есть телефон; экран не прокручивается во время игры.
- [ ] Новая игра - `version` `0.1.0`: до 1.0.0 это пререлиз, хаб показывает его только владельцу;
      1.0.0 - выход в публичный каталог, по решению владельца (D-060). Правка опубликованной -
      новый `version` (П-034).
- [ ] Концепты (арт, черновики стиля) - в `games/<id>/concepts/`: папка в `.gitignore`,
      репозиторий публичный (D-060).
- [ ] `NOTES.md` обновлён; отчёт владельцу - по образцу ниже.

**Отчёт агента** - коротко и без "всё работает":

```markdown
Итог: my-game 0.1.0 готова к приёмке / не готова: <почему>.
Проверено: <команда> - <итог>; <что смотрел глазами и где>.
Не проверено: <что и почему> (телефон, Safari, e2e - без Chromium).
Вне игры трогал: ничего / <файл - зачем>.
```

## 7. `games/<id>/NOTES.md` - память игры

Файл живёт рядом с `game.json` и **не попадает в сборку** (у `vite-ts` публикуется `dist`, у
`static` - `src`). Это мини-STATE игры: переписывается, а не дописывается, ≤ 80 строк.

```markdown
# my-game - заметки разработки

## Бриф
(раздел 3)

## Состояние
Версия 0.1.0, в работе: <шаг>. Проверено: <команда - итог>. Не проверено: ...

## Решения
- Р1. <что выбрали> - <почему>; отвергли <что>.

## Дальше
1. ...
```

Решение, которое касается не одной игры (новое право манифеста, правка SDK, общий компонент),
в `NOTES.md` не прячется - это вопрос владельцу и запись в DECISIONS.md сессией на VPS-1.

## 8. Границы агента

| Можно | Нельзя |
|---|---|
| всё в `games/<id>/` | `apps/`, `packages/`, `tools/`, `deploy/`, `.github/`, `templates/` |
| зависимости игры (`pnpm --filter @gf-game/<id> add ...`) | зависимости в корень и ядро |
| строку игры в таблицу GAMES.md | STATE, ROADMAP, DECISIONS, CHANGELOG - их ведёт сессия на VPS-1 |
| предложить правку SDK, моста, шаблона - текстом в `NOTES.md` | править SDK, мост, сервер игр (это зона роли "Безопасность") |
| `git status`, `diff`, `log` | `commit`, `push`, `merge`, новые ветки - без "да" владельца |
| чужие картинки и звуки - нет | ассеты, бренды и названия чужих игр (D-054: своё, не копия) |

Игра для платформы - **недоверенный код**: её песочницу держат сервер игр и мост, а не
вежливость игры. Поэтому агенту игры не нужен доступ к ним, а обход песочницы - не "хак ради
фичи", а дыра. Нужна возможность, которой нет в SDK, - вопрос владельцу.

Списки e2e (`tests/e2e/offline.test.ts`, `tests/e2e/hub.test.ts`) общие для всех игр: при
нескольких агентах сразу их правит не агент, а тот, кто вливает ветки в `dev`, - иначе конфликт.

## 9. Принять игру и влить в `dev`

1. Владелец читает отчёт и `NOTES.md`, играет сам (ПК и телефон, если они в брифе).
2. Коммит в ветке `game/<id>` - с "да" владельца, сообщение по-русски, суть изменений, без трейлеров.
3. PR `game/<id>` → `dev`: CI гоняет `pnpm check` целиком, включая сборку хаба и e2e.
4. После слияния сессия на VPS-1 добавляет игру в списки e2e, STATE и CHANGELOG; в `main` (прод)
   - перемоткой `dev` и отдельным "да" (D-042). Игра без нового `version` на прод не выйдет (П-034).

## 10. Если что-то странно

| Симптом | Где ответ |
|---|---|
| Архив открывается белым экраном | П-001, П-018 |
| В архиве нет картинок, в хабе - есть | П-002, П-019 |
| Сохранения в архиве пропадают | П-003: SDK падает в память, `persistent: false` |
| Полный экран, Esc, захват мыши ведут себя странно | П-047, П-048 |
| Элемент с анимацией съехал с центра | П-050 |
| "Версия уже опубликована с другим содержимым" | П-034; локально - `--replace` |
| Мало FPS в 3D | П-051 и строки F3 в `k8s-at-home` |

Нашли новые грабли - описать в `NOTES.md` (симптом → причина → обход), сессия на VPS-1 перенесёт
в PITFALLS.md следующим номером.

## Откуда эти правила

Взяты проверенные практики и подогнаны под проект:

- **`AGENTS.md`** - открытый формат инструкций для агентов: его сами читают Codex (ChatGPT),
  Cursor, Copilot и другие; ближайший к файлу `AGENTS.md` главнее. Claude Code читает `CLAUDE.md`,
  Gemini CLI - `GEMINI.md`: оба файла только подключают `AGENTS.md` (`@AGENTS.md`), текст правил -
  один, разъехаться нечему. Правило правится в `AGENTS.md`, не в обёртках.
- **Руководство Anthropic по Claude Code**: разведать → план → код → проверка; дать агенту способ
  проверить себя (тесты, скриншот), а не верить на слово; короткие файлы инструкций; параллельные
  сессии - в отдельных git worktree.
- **Длинные задачи агентов (Anthropic)**: шаг за шагом по одной функции, файл прогресса и чистое
  состояние в конце сессии - отсюда `NOTES.md` и "одна функция за раз".
- **Diátaxis**: разделение "как сделать" (разделы 1-5, 9), справочника (GAMES.md, SDK.md) и
  объяснений (раздел 8, DECISIONS.md) - каждый документ отвечает на свой вопрос.
- **Свои правила проекта**: факт - с источником, "настроено" не значит "сработало", игра - новый
  `version`, недоверенный ввод из игры, проверка мутацией защит (TESTING.md).
