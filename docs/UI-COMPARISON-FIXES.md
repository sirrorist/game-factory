# Исправления проектного UI-сравнения после ревью bd0b874

2026-10-16. Исправления R1–R3 из [независимого ревью](UI-COMPARISON-REVIEW.md).
Прежний отчёт и его доказательства не изменялись. Исходники игр, UI хаба,
production-команды, Docker и зависимости этим проходом не менялись.

## R1: актуальность работающего просмотрщика

`tests/ui/core/server.ts` перечитывает snapshot metadata и report.json при каждом
запросе `/`, `/index.html` и `/config.json`. Отчёт заново проходит проверку evidence;
отсутствующий, повреждённый или устаревший отчёт не подтверждает новую сборку.
При временном отсутствии snapshot во время пересборки сервер возвращает 503,
а открытый просмотрщик снимает успешный статус.

`compare.html` обновляет статус и metadata раз в две секунды, при возвращении во
вкладку и по кнопке «Перезагрузить». Потерявшие актуальность снимки отключаются;
если они уже открыты, просмотр переключается на состояние сборки. Обычное обновление
статуса не перезапускает iframe с живой игрой.

Браузерная регрессия оставляет viewer открытым после успешного отчёта, заменяет after
и записывает аварийный отчёт. Проверены исчезновение успеха, отключение снимков/diff,
новая версия, кнопка viewer и обычный reload браузера. HTTP-тест дополнительно
проверяет старый отчёт с несовпадающими hashes и неполный JSON.

## R2: сохранение промежуточной диагностики

Общий `trackCheck()` сохраняет отчёт атомарной заменой файла. Универсальный runner
и Superwalk записывают начатое состояние и каждый полученный снимок, измеренные
ошибки, затем diff и flows. Хаб использует тот же механизм и сохраняет каждое
завершённое состояние. Исключение записывает исходную причину; SIGINT/SIGTERM
сохраняют накопленные данные и коды 130/143 до завершения процесса.

CLI при исключении дополняет сохранённый JSON причиной отказа, не заменяет результаты
пустым статусом. Исходные hashes, профили, результаты и пути к PNG остаются в отчёте.
Проверки production-запуска и сохранности баз сохранены.

`pnpm ui:regression` запускает настоящий CLI для Snake и Superwalk. После первого
записанного снимка отдельный процесс меняет только сгенерированный after/index.html
либо посылает SIGINT. Проверены код завершения, fatal, неполный статус, evidence,
профили, ошибки и существование перечисленных PNG. Это не проверка helper-а на
заранее заполненном JSON. При контрольной подмене сохранены четыре состояния Snake
и 46 состояний Superwalk; при SIGINT — начатое состояние и уже полученный PNG.
Существующее переполнение Snake осталось в диагностике, игра не исправлялась.

Сводка собственного прогона: `test-results/ui-review-fixes/summary.json` с путями
четырёх новых именованных проходов. Прежние базы и результаты ревью не перезаписывались.

## R3: скрытые файлы через симлинки

`servedFile()` проверяет скрытые компоненты пути после `realpathSync()` относительно
корня раздачи. Ссылка на скрытый файл или файл внутри скрытого каталога блокируется,
как и прямая ссылка. Внутренние ссылки на обычные файлы остаются допустимыми.
Проверены скрытый файл, скрытый каталог, внешний симлинк и обычный внутренний;
отдельный HTTP-запрос к псевдониму скрытого файла возвращает 404.
