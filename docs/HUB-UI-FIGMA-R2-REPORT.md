# Хаб: замечания к Figma и эскиз R2

2026-10-19. **В Figma не применено: подтверждён лимит MCP Starter.**
Приложение Next и предыдущие прототипы не изменены. Рабочие документы и базы
сравнения сохранены. Commit/push/ветки/публикации нет.

Владелец оставил текущую мобильную ширину карточек и полные обложки 16:9.
Новые замечания: имя прилипает к выходу; на ПК второй ряд не заполняет экран
до нижнего края; уведомлениям нужна рамка. Снимки владельца и SHA-256 сохранены
отдельно в `test-results/ui/hub/figma-handoff-20261019/design-r2/owner-references/`.
На новом production-снимке DevTools явно указан CSS viewport 1920×1080;
физические размеры уменьшенного PNG не принимались за CSS px.

## Причина и подготовленные исправления

В Figma Header не имел отдельной группы аккаунта с gap, поэтому ник и выход
оказались вплотную. Подготовлена группа с отступом 8 базовых единиц и сохранением
всех данных/вариантов шапки. На масштабе 2 отступ будет 16 px.

В исходном Figma-кандидате естественная высота desktop-карточки — 350 единиц;
два ряда заканчиваются на y=912 как в 1920×920, так и в 1920×1080. Для последнего
остаётся 168 px снизу. В 3840×2160 конец y=1824, остаток 336 px. Ранее проверенное
«два ряда помещаются» не доказывало заполнение экрана: этот критерий был упущен.
В коде исходного хаба высота рассчитывается через visualViewport и высоту шапки;
текущий production-код/его SHA в этом этапе не проверялись. Возвращать прежний
цикл измерения карточки и root font-size через dvh не требуется.

Подготовлен отдельный desktop-вариант: высота ряда занимает половину места
после вступления с учётом промежутка между рядами и нижнего отступа 8 базовых
единиц. Обложка, название, две строки описания и кнопки сохраняют размеры;
дополнительное место располагается **после описания, до тегов**, без пустой
зарезервированной строки под коротким заголовком. В Full HD это добавляет
80 px телу каждой карточки; видимый промежуток с обычным gap — около 90 px.
Это явный компромисс заполнения высокого окна. Мобильные main components
не изменяются. В низком окне естественный минимум сохраняется, появляется скролл.

Уведомление: рамка 1 px `--line-strong`, скругление сохранено. Drawer остаётся
без border. В подготовленном Figma-патче stroke внутри и не участвует в компоновке.
Будущая общая основа Popup и её анимации в приложении ещё не реализованы.

## Что можно посмотреть сейчас

Из-за лимита Figma собран **отдельный локальный HTML-эскиз** трёх поправок.
Это не экспорт Figma и не работающий Next-хаб; авторизация и запуск игр в нём
не действуют. Он использует шрифты проекта, исходные обложки и реальные тексты
manifest. Этот эскиз не назначен новой базой реального хаба.

- [Исправленный каталог](http://127.0.0.1:4198/)
- [Контроль без трёх поправок](http://127.0.0.1:4198/?revision=before)
- [Уведомление с рамкой](http://127.0.0.1:4198/?toast=1)

Сервер слушает только loopback. Если остановлен:

```bash
# Выполнять из корня репозитория.
node test-results/ui/hub/figma-handoff-20261019/design-r2/gf-hub-design-r2.mjs --serve-only
```

Для просмотра эскиза на телефоне: `adb reverse tcp:4198 tcp:4198`, затем открыть
`http://127.0.0.1:4198/`. Это не приёмка настоящего хаба/iframe/адресной строки.

## Проверки эскиза

Команда: `node /tmp/gf-hub-design-r2.mjs` (копия в каталоге результатов).
22 случая: по before/after для 314×844, 390×844, 440×844, 844×390,
1920×920, 1920×1080, 2560×1280, 2560×1440, 3840×2160, 1920×720,
и уведомление в Night/Day. Ошибок страницы/проверок нет.

| 1920×1080 | 430 | 1072 | 8 |

| 3840×2160 | 860 | 2144 | 16 |

На 1920×720 высота остаётся 350 и второй ряд уходит под прокрутку, а не сжимает
обложки/текст. Рамка уведомления — 1 px в обеих темах и отличается от фона;
проверено, что при закрытии оно видно в середине выхода и скрыто после завершения.
Все шесть cover img загружены, object-fit contain, рамки 16:9; теги целиком
помещаются внутри своей строки. 314×844 before/after совпали побайтово;
для 390/440/landscape также сохранены измерения before/after.

В первом эскизе обнаружено столкновение одинаковых id градиентов встроенных
SVG: менялся фон Superwalk. Исправлено изоляцией SVG через img data URL.
Неудачная попытка вместе с before/after и отчётом сохранена отдельно в
`archive-inline-svg-collision/`; итоговые 22 проверки выполнены после исправления.

Независимый `menu_prototype_review` открыл восемь текущих PNG, прочитал JSON
и самостоятельно сверил SHA-256 мобильной пары. Блокирующих визуальных дефектов
не обнаружил; подтвердил зазор, низ рядов и видимую рамку обеих тем. Отдельно
отметил заметный промежуток после описания как цену заполнения экрана.
Вердикт — готово к оценке владельцем **как эскиз R2**. Его просмотр не подтверждает
анимации, Figma, настоящий сайт, касания или увеличенный текст.

## Что ещё не выполнено

Официальный `use_figma` снова вернул `Starter MCP tool call limit` до чтения/
изменения файла. Другие коннекторы для обхода лимита не использовались.
Два точных патча подготовлены в `pending-figma-header-notification.js` и
`pending-figma-desktop.js`. Проверен только JavaScript-синтаксис; они **не выполнены**
и не проверены внутри Figma. При применении сначала прочитать актуальные IDs,
обновить ledger возвращёнными IDs, сделать экспорт и независимый просмотр.
Фреймы и геометрия исходного Figma-файла пока остаются прежними.

CSS эскиза использует стабильный svh только для desktop-рядов. Формула привязана
к вступлению этого эскиза; переносить её как готовое универсальное решение
в настоящий каталог нельзя без проверки длинного текста, иной шапки и числа игр.
Это остаётся работой пунктов 2–5 вместе с реальным Next/iframe, устройством и CI.
