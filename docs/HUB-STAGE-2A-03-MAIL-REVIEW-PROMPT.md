его последующего явного решения. Проверяющего запускает владелец. Копировать текст ниже; основной агент не вызывает
подагента. [Утверждённый план R2](HUB-STAGE-2A-03-MAIL-PLAN.md),
[отчёт реализации](HUB-STAGE-2A-03-MAIL-REPORT.md).

Проведи независимое read-only ревью локальной реализации первого почтового подшага 2А-03.
R2 и четыре исправления после предыдущего ревью утверждены владельцем.
Провайдер Resend Free принят, собственная почта отложена. Сначала перепроверь
сквозное окно 24 часа, dropRequest, метаданные незавершённого ответа и негативный
потоковый тест. Отдельно оцени согласованное уточнение теста общего дедлайна:
теперь допускается только ECONNRESET либо 503/unknown с cancelled/transport_error;
count=1 и отмена upstream обязательны. Последний целевой прогон 56/56, обе проверки
типов пройдены. Эти сведения отчёта не приравнивать к собственному запуску.
Не начинай повторный полный разбор 2А-02 или обсуждение выбора провайдера.

Прочитай AGENTS.md, CLAUDE.md и применимые инструкции. Затем:
docs/SECURITY.md;
docs/HUB-STAGE-2A-03-MAIL-PLAN.md — целиком;
docs/HUB-STAGE-2A-03-MAIL-REPORT.md;
docs/HUB-MAIL-OPERATIONS.md;

Для контекста D-038/D-063 и границы auth достаточно текущего compose.prod.yml,
auth.ts/auth-core.ts и соответствующих разделов общего плана 2А.
Материалы предоставлены в test-results/mail-r2-review относительно корня:
gf-mail-r2-review.patch — новые файлы R2 целиком и точный diff текущего шага
существующих документов; gf-mail-deadline-review.patch — точный diff только
согласованного уточнения теста и документов. Есть также снимок current и manifest.json.
Старый общий baseline из временной директории недоступен: пакет не притворяется
полным Git-diff предыдущих изменений существующих файлов. Читай актуальные
исходники из списка выше и явно укажи границы своего вывода. Копия первого пакета
есть в /tmp/gf-mail-r2-review.patch; долговременный путь предпочтительнее.
Это материалы для чтения, не для применения. Git не использовать.

Проверь соответствие R2 по исходникам:
- строгий разбор четырёх полей, дубли, mailbox/URL/HTML, фиксированный возврат в будущем;
- закрытый запуск, разделение секретов, фиксированный POST Resend, запрет redirect/proxy;
- все абсолютные дедлайны, фактические байты, лимиты соединений и обработок,
  pipeline, завершение отмены/чтения, освобождение ресурсов;
- единый бюджет повторов, неизменность ключа/payload между вызовами, pin и смена
  отправителя/шаблона, старый профиль, неизменность X-GF-Mail-Expires-At и окно
  перед каждой попыткой/паузой, сокращение таймаута клиента, монотонный предел;
- обоих 409, скорость/квоты, Retry-After, сохранение unknown после другого отказа;
- сохранение только безопасных метаданных при обрыве/размере/таймауте после
  заголовков; отсутствие автоматического повтора, включая truncated/oversized 502/429;
- unknown без автоматического повтора для неизвестных 5xx, отдельно от распознанных 500/503;
- отсутствие реальных адресов/токенов/секретов/ID в логах, ответах и исключениях;
- ограничения compose-примера и точность условий реального включения;
- содержательность проверок; не приравнивай подмену HTTP к реальным TLS/сетям/доставке.

Новые кодовые пути auth, Q3, настоящие DNS/секреты, сеть и реальная отправка сюда не входят.
Их отсутствие не считать дефектом этого подшага. Возможный пробел защиты транспорта
при таком объёме, напротив, укажи конкретно. Не принимай сведения отчёта о тестах
за самостоятельно воспроизведённый результат.

Работай только чтением: без правок, Git-команд, подагентов, запуска приложения,
тестов, сборок, установки зависимостей, миграций и запросов к рабочей инфраструктуре.
Не читать .env, deploy/secrets, ключи и персональные данные; не отправлять письма.
Допустима сверка публичной официальной документации.

Начни с краткого вердикта. Для каждой находки — приоритет, файл/строка,
конкретный сценарий и минимальное исправление. Отдельно — непроверенное и решения
владельца. Не объявляй отсутствие будущей реализации обнаруженной уязвимостью.
