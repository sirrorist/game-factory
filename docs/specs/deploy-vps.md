# Спецификация: деплой на VPS за существующим Traefik

> Задание для сессии агента **на VPS** (владелец запускает её там после хэндовера сессии №2).
> Решение владельца: разворачиваемся сейчас, за уже настроенным Traefik с сертификатами (D-033).
> Прежде чем что-то менять - прочитать `CLAUDE.md`, `docs/STATE.md`, этот файл,
> `docs/DEPLOY.md`, `docs/SECURITY.md`, `docs/PITFALLS.md`.

## Цель

1. Хаб - `https://games.youranus.ru`, игры - `https://<id>.play.youranus.ru`,
   служебный хост игр (архивы, обложки) - `https://play.youranus.ru`.
2. Выкладка без ручной сборки на сервере: пуш в `main` → CI собирает образы → VPS их
   подтягивает и перезапускает. Откат - на прошлый тег одной правкой.
3. Все инварианты безопасности из `CLAUDE.md` действуют и в проде, и проверены на нём.

**Не цель:** Postgres, Valkey, MinIO, авторизация (этап 1-2); отдельный домен для игр (этап 5).

## Правила, которые здесь особенно важны

- **Чужая машина** (правило кита): всё, что меняет состояние VPS - конфиги, службы,
  пакеты, файрвол, ключи, `docker compose up`, - агент готовит **блоками команд**
  (над каждым: машина, пользователь, оболочка; откат - отдельным блоком) и **ждёт**,
  пока владелец выполнит. Читающие команды (`docker ps`, `cat`, `curl`) - сам.
- **Секреты** (токен GHCR, если понадобится): только скрытый ввод (`read -s`,
  `systemd-ask-password`), проверка по длине, никогда в командной строке и в репозитории.
- **Не предполагать состояние сервера** - проверить командой (раздел "Разведка").
- Коммиты в репозиторий - прямо в `main`, одним коммитом, с "да" владельца (D-030).
  Минуты CI беречь (D-031): проверять локально, не пушить по мелочи.

## Шаг 0. Разведка (только чтение, до любых правок)

Записать ответы в `docs/STATE.md` → раздел "VPS":

| Что узнать | Чем |
|---|---|
| ОС, архитектура (amd64/arm64 - от этого зависит платформа образов) | `uname -m`, `cat /etc/os-release` |
| Docker и Compose, версии | `docker version`, `docker compose version` |
| Как запущен Traefik: контейнер/служба, версия (v2 или v3 - разный синтаксис `HostRegexp`) | `docker ps`, `docker inspect` |
| Откуда Traefik берёт маршруты: docker-метки (provider docker) или файлы (provider file) | статическая конфигурация Traefik |
| Имя certresolver, тип вызова (DNS-01 или HTTP-01), DNS-провайдер | статическая конфигурация, `acme.json` - **только наличие доменов, не содержимое ключей** |
| **Есть ли сертификат на `*.play.youranus.ru`** | список доменов в хранилище ACME или `openssl s_client -connect <ip>:443 -servername x.play.youranus.ru` |
| Сеть Docker, в которой Traefik видит сервисы | `docker network ls`, `docker inspect` |
| DNS: `games`, `play`, `*.play` смотрят на VPS | `dig +short games.youranus.ru play.youranus.ru test.play.youranus.ru` |
| Свободное место, память, что ещё крутится | `df -h`, `free -h`, `docker ps` |

**Главная ловушка:** сертификат `*.youranus.ru` **не покрывает** `x.play.youranus.ru`
(wildcard - ровно одна метка, П-004). Нужен отдельный `*.play.youranus.ru`, а он
выдаётся только через DNS-01. Если Traefik умеет только HTTP-01 - остановиться и
спросить владельца (нужен API DNS-провайдера, см. DEPLOY.md "Сертификаты").

## Шаг 1. Изменения в репозитории

### 1.1. Образ `games` - публикация игр в том данных

Сейчас игры собираются на хосте и монтируются в `/data` (D-027). В проде собирать на
хосте нечем и незачем. Нужна цель `games` в `Dockerfile`: исходники + зависимости +
`tools/gf.ts`; команда по умолчанию - `gf build && gf export` в `GF_DATA_DIR=/data`.

Запускается одноразово перед `up -d` с **постоянным** именованным томом `gf-data`.
Так инвариант 2 (версия неизменяема) работает и в проде: `gf build` откажет, если
содержимое игры поменялось без смены `version`, и выкладка остановится на старой версии,
а не подменит опубликованную. Это поведение - критерий приёмки (ниже).

`hub` и `play` монтируют `gf-data` **только для чтения**.

### 1.2. `deploy/compose.prod.yml`

Отдельный от `docker-compose.yml` (тот - стенд разработчика на 127.0.0.1).

- Сервисы `hub`, `play`, одноразовый `games` (профиль или `docker compose run --rm`).
- Образы `ghcr.io/sirrorist/game-factory-{hub,play,games}:${GF_IMAGE_TAG}` - тег из `.env`
  на сервере (коммит `main`); откат - поменять тег и `up -d`.
- **Портов наружу нет** - только сеть Traefik (внешняя, имя из разведки).
- Ужесточение как в `docker-compose.yml`: `read_only`, `cap_drop: [ALL]`,
  `no-new-privileges`, пользователь `node`; плюс лимиты памяти и ротация логов
  (`logging: { driver: json-file, options: { max-size: 10m, max-file: "3" } }`).
- Docker-сокет не монтируется ни в один наш контейнер (SECURITY.md).
- Окружение:

| Сервис | Переменная | Значение |
|---|---|---|
| play | `GF_PLAY_BASE_HOST` | `play.youranus.ru` |
| play | `GF_HUB_ORIGINS` | `https://games.youranus.ru` - **и только он**, без `localhost` |
| play | `GF_PLAY_HOST` / `GF_PLAY_PORT` | `0.0.0.0` / `4100` (уже в образе) |
| hub | `GF_PLAY_PUBLIC_ORIGIN_TEMPLATE` | `https://{id}.play.youranus.ru` |
| оба | `GF_DATA_DIR` | `/data` (уже в образе) |

### 1.3. Маршруты Traefik

Метками в `compose.prod.yml` (если Traefik на provider docker) или файлом - как устроено
у владельца. Смысл:

| Роутер | Правило | Сервис | TLS |
|---|---|---|---|
| hub | `Host(\`games.youranus.ru\`)` | hub:3000 | сертификат `games.youranus.ru` |
| play | `Host(\`play.youranus.ru\`) \|\| HostRegexp(<*.play>)` | play:4100 | `*.play.youranus.ru` + `play.youranus.ru` |

- `HostRegexp` в Traefik v3: `` HostRegexp(`^[a-z0-9-]+\.play\.youranus\.ru$`) ``;
  в v2 синтаксис другой (`{sub:[a-z0-9-]+}.play.youranus.ru`) - проверить версию.
- Traefik **обязан передавать исходный `Host`** (по умолчанию так): play-server по нему
  решает, какая игра (`classifyHost`). Никаких middleware, переписывающих Host.
- Не добавлять middleware, которые трогают `Content-Security-Policy`,
  `Permissions-Policy`, `Cross-Origin-*` ответов play-server - они часть песочницы
  (инвариант 5). Сжатие (compress) - можно.
- Редирект HTTP → HTTPS - да. HSTS - только на эти хосты и **без** `includeSubDomains`
  на `youranus.ru`, если владелец явно не решит иначе: это заденет все поддомены зоны.

### 1.4. CI: публикация образов

Новый workflow `publish.yml` (или задача в `docker.yml`):

- на пуш в `main` **после** зелёного `CI` (`workflow_run` по `CI` с `conclusion == success`)
  и вручную; не на PR;
- сборка целей `hub`, `play`, `games` под архитектуру VPS (из разведки), пуш в GHCR
  с тегами `<sha>` и `main`;
- права: `contents: read`, `packages: write` - только этому workflow;
- не собирать, если изменилась только документация (D-031).

### 1.5. Доставка на VPS - рекомендация: pull с сервера

| Вариант | За | Против |
|---|---|---|
| **А. Таймер на VPS** (systemd timer раз в 5 мин): `pull` → если тег `main` сменился - `games` → `up -d` | в GitHub нет ключей от сервера; нет входящих соединений | задержка до 5 мин |
| Б. Workflow по SSH, ключ с `command=` в `authorized_keys` | мгновенно | ключ от сервера лежит в GitHub; нужна защита Environment |
| В. Self-hosted runner на VPS | просто | **репозиторий публичный**: код из чужих PR может выполниться на VPS - **не использовать** |

Рекомендуется **А**. Скрипт `deploy/update.sh` (в репозитории) + unit-файлы
`deploy/gf-update.{service,timer}`. Скрипт: `set -euo pipefail`, лок от параллельного
запуска (`flock`), сперва `games`, и только при его успехе - `up -d hub play`;
запись в журнал (`journalctl -u gf-update`). Если образы в GHCR публичные (репозиторий
публичный) - токен не нужен; если приватные - токен только `read:packages`, вводится
скрыто.

## Шаг 2. Выкладка

Порядок для владельца (блоки команд готовит агент): каталог `/opt/game-factory`
(или как принято у владельца) → `compose.prod.yml` и `.env` с `GF_IMAGE_TAG` →
первый ручной прогон `deploy/update.sh` → проверки ниже → включение таймера.

## Критерии приёмки

Каждый - командой или в браузере, результат записать в STATE ("проверено"):

1. `https://games.youranus.ru` - каталог из трёх игр с обложками.
2. Каждая игра открывается в хабе, `#mode` = "в хабе", рекорд виден в хабе.
3. "Скачать" отдаёт `<id>-1.0.0.zip`; распакованный архив работает двойным кликом.
4. Заголовки (`curl -sI`):
   - `https://snake.play.youranus.ru/` - `Content-Security-Policy` с
     `frame-ancestors https://games.youranus.ru` (и ничем больше), `X-Content-Type-Options`,
     `Permissions-Policy`, `Cross-Origin-Opener-Policy`;
   - `https://games.youranus.ru/` - `frame-ancestors 'none'`, нет `X-Powered-By`.
5. Изоляция: `https://play.youranus.ru/index.html` - 404 (служебный хост не отдаёт игры,
   инвариант 1); `https://nope.play.youranus.ru/` - 404; запрос с
   `Service-Worker: script` к игре - 403.
6. Сертификат для `x.play.youranus.ru` валиден (`curl` без `-k`).
7. Порты 3000 и 4100 **не** доступны снаружи (проверка с другой машины или `ss -tlnp`).
8. Выкладка: пуш в `main` → через ≤ 10 мин на VPS работают образы с новым тегом
   (`docker compose ps` / `docker inspect`), журнал `gf-update` без ошибок.
9. Откат: прошлый `GF_IMAGE_TAG` → `up -d` → работает прошлая версия.
10. Неизменяемость: изменить игру без смены `version` → `games` падает с "неизменяема",
    хаб и игры продолжают работать на старом (проверить на временной ветке или локально
    с копией тома - **не** на опубликованной игре в `main`).
