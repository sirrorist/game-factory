## Оставшаяся проблема R1 — P2

**Файл и строки:** `tests/ui/compare.html:115–120`. Автоматическое обновление заменяет
config, подпись версии/ref и статус, но вызывает только `showReport()`. Загруженный
документ iframe при смене hash остаётся прежним. Это касается и режима «Одинаковое
состояние», поэтому сохранение живого игрового сеанса само по себе проблему не объясняет.

**Воспроизведение:** на новом синтетическом сравнении открыть after с явным маркером
версии; оставить viewer в режиме одинакового состояния. Через `publishSnapshot()`
заменить after другим HTML и записать завершённый успешный report с актуальными
`snapshotEvidence()`. Дождаться автоматического `/config.json` без нажатия «Перезагрузить».
В пробе использована та же проверка evidence, что и в инструменте; HTTP отдаёт новую сборку.

**Ожидается:** содержимое iframe соответствует показанной версии. Если живой кадр
сохраняется намеренно, его прежняя версия и необходимость обновления должны быть явно
обозначены; успешную новую проверку нельзя показывать как подтверждение старого кадра.
Опрос при неизменном артефакте не должен перезапускать игру.

**Фактически:** справа подпись «После 4», ref `checked-v4`, успешный полный прогон,
но внутри iframe остаётся `BUILD 3`. Прямой GET origin after возвращает `BUILD 4`;
report содержит актуальные hash/artifactHash, проверка evidence проходит. Время запуска
iframe не изменилось. Полный reload браузера или кнопка viewer загружает верный документ.

**Доказательства:** [снимок](../test-results/review-ui-fixes-recheck/details/successful-rebuild-auto.png),
[данные](../test-results/review-ui-fixes-recheck/details/viewer.json), строки наблюдений
`successful-rebuild-auto`, `browser-reload`, `unchanged-success-poll`.
Самодостаточный сценарий: `test-results/review-ui-fixes-recheck/viewer-details.mjs`.
При повторении выбрать новый каталог, чтобы сохранить эти доказательства.
Обе самостоятельные пробы дали одинаковое расхождение, PNG открыт отдельно.

Исходный вариант R1 с упавшим повторным check исправлен: сервер перечитывает metadata/report,
старый успех снимается, `option.disabled` становится true. При отсутствии snapshot `/config.json`
возвращает 503, при повреждённом report успех также снимается. `/`, `/index.html` и
`/config.json` возвращают свежую конфигурацию. Кнопка viewer и reload браузера обновляют кадр.
При неизменном артефакте периодический опрос действительно сохраняет время запуска iframe.

Регрессия из `check-failures.browser.ts` проверяет неуспешный новый отчёт и последующую
ручную перезагрузку. Смену успешной сборки при остающемся открытым кадре она не проверяет,
поэтому её прохождение не закрывает описанный случай.
