# Грабли

Формат: **симптом** → причина → как обходить → где это держится (тест, код).
Дописывается каждый раз, когда наступили. Номер не переиспользуется.

## Браузер и офлайн

**П-001. Игра из архива открывается белым экраном.**
Причина: `<script type="module" src="…">` через `file://` блокируется как cross-origin
(у `file://` origin `null`). Обход: классические скрипты или весь код внутри HTML.
Держится: `gf export` отказывает (`offlineProblems`), e2e `offline.test.ts`.

**П-002. В архиве не грузятся уровни и спрайты через `fetch()`.**
Причина: `fetch` и `XMLHttpRequest` к `file://` запрещены. Обход: `<img>`, `<audio>`,
встраивание в бандл (`data:`), для Phaser - загрузка картинок через `HTMLImageElement`.
Держится: предупреждение `gf export`.

**П-003. Сохранения в архиве пропадают или бросают исключение.**
Причина: в части браузеров и в приватном режиме `localStorage` на `file://` недоступен
или бросает. Обход: SDK проверяет хранилище пробной записью и падает в память
(`persistent: false`). Держится: `gf-sdk.js` `safeStorage`.

## Домены и cookies

**П-004. Нельзя сделать `*-play.youranus.ru`.**
Причина: wildcard в DNS и в сертификатах - только на целую левую метку.
Обход: `*.play.youranus.ru` (D-009).

**П-005. SameSite-cookies не защищают хаб от запросов из игр.**
Причина: `games.youranus.ru` и `x.play.youranus.ru` - один регистрируемый домен, то есть
same-site. Обход: CSRF-токены + проверка `Origin`, кука `__Host-`; окончательно -
отдельный домен для игр (D-010).

**П-006. Игры могут ставить cookies на весь `youranus.ru`.**
Причина: тот же общий домен. Обход: префикс `__Host-` у кук хаба (запрещает `Domain`, и
чужая кука с тем же именем не пройдёт). Окончательно - отдельный домен + Public Suffix List.

**П-007. Локально `x.play.localhost` не резолвится.**
Браузеры (Chromium, Firefox) резолвят `*.localhost` в 127.0.0.1 сами - проверено в
Chromium через Playwright. А вот `curl` и Node - нет: им передавай заголовок `Host`
и стучись в `127.0.0.1` (так сделаны `server.test.ts` и примеры в DEVELOPMENT.md).

## Сервер игр

**П-008. Service Worker игры продолжает отдавать старую или снятую версию.**
Причина: SW живёт в браузере на origin игры, пока его явно не снимут. Обход: play-server
отвечает 403 на запрос скрипта SW (D-018). Если SW когда-то понадобится -
вместе с `Clear-Site-Data` при снятии версии.

**П-009. Обложка SVG, открытая напрямую, выполняет скрипты.**
Причина: SVG - документ, внутри может быть `<script>`. Обход: служебный хост отдаёт
всё с CSP `sandbox`. Держится: `server.test.ts`.

## Node и TypeScript

**П-010. `SyntaxError` на `enum` или `namespace` при запуске `.ts`.**
Причина: Node только стирает типы и не умеет генерировать код. Обход: стираемый синтаксис
(`erasableSyntaxOnly` в tsconfig ловит заранее), union-литералы вместо `enum`.

**П-011. `ERR_MODULE_NOT_FOUND` на импорт без расширения.**
Причина: Node ESM требует полный путь. Обход: `import … from './x.ts'`
(`allowImportingTsExtensions`).

**П-012. `.ts` из `node_modules` не исполняется.**
Причина: Node не стирает типы в файлах под `node_modules`. Поэтому ядро импортирует
пакеты рабочей области относительными путями, а не по имени `@gf/…`.

**П-013. `import.meta.url === 'file://' + argv[1]` ломается на путях с пробелами.**
Обход: `pathToFileURL(process.argv[1]).href` (`tools/gf.ts`).

## Облачная среда агента

**П-014. `npm install` отвечает 403 `Host not in allowlist: registry.npmjs.org`.**
Причина: сетевая политика окружения Claude Code. `registry.npmjs.org` ходит мимо
общего прокси, и то, что другие домены из списка открылись сразу, для него не сработало.
Обход: владелец открывает домен в настройках окружения; если не помогло - новая сессия.
Пока закрыто - работа без зависимостей (D-013), lockfile ждёт.
Сессия №2 (2026-09-25): в новой сессии реестр открыт (`curl` → 200) - обход "новая
сессия" подтвердился.

**П-015. `pnpm import` не делает lockfile из `package-lock.json` без сети.**
Причина: pnpm всё равно ходит в реестр за метаданными. `npm install --offline
--package-lock-only` из кеша работает, но pnpm-lock из него не получить.

## Тесты

**П-016. Негативный тест зелёный, но ничего не проверяет.**
Пример: `sed`-мутация `frame-ancestors` не применилась (шаблон не совпал), тест
"прошёл" - на неизменённом коде. Обход: после мутации проверять, что она легла
(`grep`), а после отката - сверять файл побайтно (`cmp` с копией). См. TESTING.md.

**П-017. e2e "змейки" падает в CI, хотя локально зелёный.**
Симптом: `'Новый рекорд: 1!'` вместо `Игра окончена` (CI #1, 2026-09-25). Причина: еда
ставится через `Math.random` и изредка ложится на путь змейки - тест зависел от
случайности. Обход: тест фиксирует `Math.random` через `page.addInitScript`. Правило:
e2e не опирается на случайность игры - её фиксируют, а не "перезапускают до зелёного".

## Сборка игр (Vite)

**П-018. Офлайн-сборка падает: top-level `await` в формате IIFE.**
Причина: `@gf/vite-config` собирает игру классическим скриптом (IIFE), а там
`await` вне функции невозможен. Обход: весь запуск - в `async function main()`,
вызов `void main()` (так в шаблоне `vite-ts`).

**П-019. Движок в архиве не находит картинки, в хабе - находит.**
Та же причина, что П-002: загрузчик Phaser/Three ходит за файлом через XHR/fetch.
Обход: `import url from './a.png'` (станет `data:`-URL) или рисовать текстуры кодом (D-029).

## Next.js

**П-020. `next build`: "this filesystem access causes the whole project to be traced".**
Причина: `path.resolve(process.cwd(), …)` в серверном коде - трассировщик Next не знает,
что это путь к данным, и тащит весь проект в сборку. Обход: `/*turbopackIgnore: true*/`
в аргументе (`apps/hub/src/lib/config.ts`).

**П-021. `next start` предупреждает и отказывается работать с `output: 'standalone'`.**
Обход: `standalone` только при `GF_HUB_STANDALONE=1` - в Docker-образе (D-027).

**П-022. `next dev` переписывает `apps/hub/tsconfig.json`.**
Раскрывает массивы по строке и дописывает `.next/dev/types/**/*.ts` в `include`. Это
нормально: держим файл в том виде, который Next оставляет, иначе дифф после каждого запуска.

## Браузер (e2e)

**П-023. WebGL в безголовом Chromium: "Automatic fallback to software WebGL has been deprecated".**
Причина: без GPU Chromium рисует WebGL программно (SwiftShader), и молчаливый откат на
него объявлен устаревшим - однажды Three.js просто останется без WebGL. Обход: запуск
с `--enable-unsafe-swiftshader` (`launchBrowser` в `tests/e2e/helpers.ts`).

**П-024. Предупреждение `Unrecognized feature: 'bluetooth'` в консоли игры.**
Chromium не знает `bluetooth` в `Permissions-Policy` play-server. Безвредно (лишняя
директива игнорируется), e2e ловит только ошибки консоли. Убирать не спешим: другие
браузеры директиву знают.

## Облачная среда агента (Docker)

**П-025. `docker info`: "failed to connect to the docker API".**
В контейнере агента `dockerd` установлен, но не запущен. Обход: `dockerd &` (своя
одноразовая машина агента, не чужая).

**П-026. `docker build`: `429 Too Many Requests` от `registry-1.docker.io`.**
Лимит анонимных скачиваний Docker Hub с общего IP. Обход: зеркало -
`docker compose build --build-arg NODE_IMAGE=mirror.gcr.io/library/node:22-bookworm-slim`
(или `public.ecr.aws/docker/library/node:…`).

**П-027. `docker build`: `SELF_SIGNED_CERT_IN_CHAIN` на скачивании pnpm/пакетов.**
Причина: исходящий HTTPS среды агента идёт через TLS-прокси со своим CA, которого нет
в образе. Обход: необязательный build-secret -
`docker build --secret id=extra_ca,src=/root/.ccr/ca-bundle.crt …` (в образ не попадает).
`docker compose build` секрет не передаёт - собирать образ хаба `docker build`, потом
`docker compose up --no-build`.

**П-028. Мутационный прогон "зелёный", потому что вывод теста потерялся.**
Вариант П-016: вывод прогона фильтровался `sed "s/^/[$f] /"`, а в `$f` путь со `/` -
`sed` падал, и строк `not ok` просто не было видно. Правило: после мутации смотреть на
явное `not ok`, а не на отсутствие `ok`.

**П-029. После `next dev` в `apps/hub/` появляются `AGENTS.md` и `CLAUDE.md`.**
Их пишет сам Next 16 (`next/dist/server/lib/generate-agent-files.js`): "читай доки Next
из `node_modules/next/dist/docs/`, API изменились". Правила агентов в проекте задают кит
и корневой `CLAUDE.md`, но этот совет полезен и узок (только про Next), поэтому владелец
решил держать файлы в репозитории (2026-09-25): удалишь - `next dev` вернёт их незакоммиченной
правкой. По API Next 16 сверяться с `apps/hub/node_modules/next/dist/docs/`.

**П-030. e2e: `Executable doesn't exist at /opt/pw-browsers/chromium_headless_shell-1243/…`.**
Причина: Playwright в lockfile новее браузера, который предустановлен в облачной среде
агента (там `chromium-1194` от Playwright 1.56), а скачать свой нельзя. Обход:
`GF_CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm test:e2e` - `launchBrowser` возьмёт готовый
браузер. В CI переменная не нужна: там `playwright install` ставит свой.

**П-031. e2e на полном Chromium: `Failed to load resource: 404` в консоли хаба.**
Причина: полный Chromium запрашивает `/favicon.ico`, а безголовая сборка - нет, поэтому
раньше не всплывало. Обход: иконка хаба `apps/hub/src/app/icon.svg` (Next сам ставит `<link rel="icon">`).

**П-032. `$` в метках Traefik внутри compose-файла.**
Compose подставляет переменные и в метках: `HostRegexp(`...ru$`)` превратится в пустую
подстановку или ошибку. В `compose.prod.yml` - `$$`, Traefik получает один `$`.
`docker compose config` печатает обратно `$$` - это экранирование вывода, не ошибка.

**П-033. `workflow_run` срабатывает на любое завершение CI.**
И на красный, и на CI из PR (в том числе из форков публичного репозитория). Без условия
`conclusion == 'success' && event == 'push' && head_branch == 'main'` Publish выложил бы
сломанный или чужой код. И собирать надо `workflow_run.head_sha`, а не голову `main` -
она могла уйти вперёд. Ручной запуск - только с `main`, иначе тег `main` получит ветка.

**П-034. Обновление движка без смены `version` - прод отказывается публиковать.**
Бандл Vite зависит от версий Phaser/Three/Vite. Dependabot поднял зависимость → содержимое
`dist` другое → `gf build` на сервере: "версия уже опубликована с другим содержимым",
выкладка стоит (хаб и игры работают на прежних образах). Это правильное поведение, не баг:
после обновления зависимостей игр поднимать `version` у затронутых игр.

**П-035. На VPS-1 репозиторий клонируется по своему SSH-ключу, а не по HTTPS.**
Правило машины: у каждого репозитория - свой ключ развёртывания и свой `Host` в
`~/.ssh/config` (`github-game-factory`), remote - `github-game-factory:sirrorist/game-factory.git`.
`git@github.com:…` даёт `Permission denied (publickey)`: общего ключа у `git-worker` нет.

**П-036. Агент на VPS-1 не видит Docker.**
`git-worker` не в группе `docker` и без `root`: `docker ps`, `docker compose`, журнал
`gf-update` - только блоком команд для владельца. Прод-образы агент локально не собирает;
их проверяет `docker.yml` в CI.

**П-037. Сертификат `*.play.youranus.ru` выпускается у Timeweb около часа; пока его нет - `x.play` отвечает `tlsv1 unrecognized name`.**
2026-09-25: `Obtaining bundled SAN certificate` для `play` + `*.play` в 18:55Z, сертификат
появился около 19:50Z. Всё это время Traefik (`sniStrict: true`) рвал TLS для имён без
сертификата. Под `_acme-challenge.play` второе значение TXT появилось на NS спустя долгое
время после первого - поэтому сначала казалось, что Timeweb держит одно значение. Это
**неверно**: пара выпустилась. Настройку всё равно сузили до `*.play.youranus.ru` (сам
`play` покрыт `*.youranus.ru`): одно значение TXT - меньше ждать при следующих выпусках.
Правило: новый wildcard через `dns01` выпускать заранее, не в момент выкладки, и ждать до
часа, а не делать выводы через 15 минут. Старые TXT-записи lego за собой не убрал -
подчистить через API Timeweb.
