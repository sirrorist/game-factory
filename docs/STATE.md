## Хэндовер: новая сессия

1. Первая строка ответа - канарейка (правило кита), нумерация ходов с 1.
2. `CLAUDE.md` ("Где работает агент"), этот файл, `docs/ROADMAP.md`, `docs/PITFALLS.md`.
3. **VPS-1, единственное место работы (D-049):** копия `dev`, копия `main` - только смотреть
   (П-041); сначала `git fetch`. Docker и root - только блоками владельцу (П-036).
   Локальная проверка - `CLAUDE.md`, "Команды"; ожидается 59 юнит и 8 `test:db` (при свободной памяти, П-043). Сборка хаба и e2e - CI.
   Пуш - блоком владельцу; в `main` = выкладка на прод через ≤ 15 минут: красный CI не
   выкладывается, игра без смены `version` - тоже (П-034).
4. **Сабагенты - Sonnet 5.5 / `high`**; какая модель работала - по полю `model` в журнале (П-042).
   Хук типографики меняет тире и кавычки на `-` и `"` - не спорить с ним (правило кита).
5. **Правка play-server, моста, SDK, `deploy/`, авторизации** - через роль "Безопасность"
   (`.claude/agents/security.md`, ROLES.md); её отчёт - заявка, находки сверять по адресам.
6. **Публичный репозиторий (D-039, D-043):** ничего о сервере сверх веб-адреса, домена и
   файлов `deploy/` нашего проекта; перед коммитом - проверка по списку D-043.

Контекст решений, который легко потерять:
- Игры собираются в CI, сервер только публикует (D-034); прод-конфиг - копии root (D-035).
- Веб - на отдельном адресе сервера (D-036). Репозиторий и образы публичные (D-037).
- Домен игр сейчас `*.play.youranus.ru`; новый домен - перед открытием (D-010).
- Офлайн-архив - только для статических игр (D-012). Хаб - гость без авторизации (D-024).
- Коммит - в `dev`, один на сессию, с "да" владельца; в `main` - перемоткой и отдельным "да"
  (D-042, заменило D-030). Минуты CI беречь (D-031).
- Метка содержимого (`contentTag`) - в ETag игр и обложки; на ней держится `check-prod`
  (D-044) - формат ETag не менять молча.
- Изоляция прода (D-038): хаб и сервер игр без интернета и без соседей - если хабу понадобится
  внешний API, это решение, а не правка compose.
