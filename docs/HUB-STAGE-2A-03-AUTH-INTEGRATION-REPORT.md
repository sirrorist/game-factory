# Закрытый A: подготовка standalone/browser-стенда

2026-10-29. Владелец разрешил реализацию: «делай», после ревью плана без
блокирующих находок и с двумя уточнениями доказательности. D-065.

## Что изменено

- Новый auth-a-integration job: contents read, отдельный пустой Postgres service
  по прежнему закреплённому digest, синтетические credentials, Chromium.
  Прежние check/mail-image не переписаны. Нет публикации и настоящих secrets.
- Явные команды test:auth-integration и test:auth-harness. Интеграционные файлы
  не попадают в старые test/e2e globs. Новых npm-зависимостей нет.
- Harness строит один production standalone с обеими закрытыми метками,
  но без DB/origin/runtime-ключей; затем копирует standalone/static/public вне
  checkout. Runtime запускается штатным server.js, register не вызывается вручную.
- Next получает только allowlist окружения и подключение gf_hub; env-файлы
  при build запрещены проверкой имён, их содержимое harness не читает.
  Файловое чтение ограничено layout и искусственными fixtures. Внешние symlink
  отвергаются; child processes/workers/native addons не разрешены.
- HTTPS-прокси сохраняет настоящий HTTPS origin и Secure/CSRF cookies.
  mail-relay:4102 — loopback alias только одноразового runner; production URL
  клиента сохранён. Управляемый collector не обращается к провайдеру.
- Файловая независимость проверяется через ту же границу spawn/start, что сервер:
  искусственная абсолютная внешняя зависимость доступна положительному контролю
  и получает ERR_ACCESS_DENIED в режиме runtime. Это не sandbox для чужого кода.
- Referer: свежий browser context, наблюдение до navigation, обязательные
  успешные CSS/JS/fonts на браузерной и серверной границе; отдельные fetch/probe
  с уникальными URL. Непоступивший запрос — ошибка. Контрольная страница unsafe-url
  обязана передать известный несекретный Referer локальному HTTPS-сборщику.

## Подготовленные интеграционные сценарии

Матрица двух runtime-флагов и неверных ключей одного build; SSR/hydration/submit
обеих форм; ответ request до результата удержанной доставки; стабильный intent
и новое явное действие; preview/GET без consume; явный одноразовый POST; reset
с отзывом сессий/passkey без авто-входа и изменения игровых данных.

Сессия B не потребляет ссылку A, чистый context её применяет. Срок/отзыв/роль/
обязательный guard перепроверяются при consume. Запросы неизвестной/запрещённой
учётки получают тот же публичный ответ, без письма; полная Q3 этим не доказывается.
Origin/CSRF проверяются прямым HTTP независимо от CORS. Альтернативные Better Auth
пути получают полноценный вход и должны вернуть именно явный guard-отказ;
регистрация — код отключённой конфигурации, а не отказ разбора неполного тела.

Autoload без auth-запроса; максимум два удержанных HTTP; точный committed prepared
виден другим backend перед ответом collector; accepted/not_accepted/unknown/обрыв
без повторной отправки. Restart pending сохраняет ID/createdAt. SIGKILL/SIGTERM
после committed started ведут к unknown без resend; timestamp старится только
у искусственной записи. SIGSTOP перед второй fixture исключает гонку теста
с самим сигналом остановки. Все дочерние процессы/браузеры/порты/файлы убираются
в finally, при timeout и обрабатываемых SIGINT/SIGTERM. SIGKILL самого runner
не даёт гарантии выполнения JS-cleanup; runner и service БД одноразовые.

При первоначальной подготовке сценарии были написаны, **не запущены**.
Первый CI и последующие локальные исправления описаны ниже.
Если CI обнаружит несовместимость runtime с Next, отдельно показать причину
и минимальный план исправления; auth/adapter/transport в этом подшаге не менялись.

Первый запуск в sandbox дал EPERM на listen loopback: он не засчитан за успех.
HTTP/HTTPS-пробы повторены с разрешением выхода из sandbox; это не открывает
рабочую сеть/инфраструктуру. OpenSSL создавал только искусственный сертификат.
Ранние ошибки типов (parameter properties и narrowing длины массива) исправлены.

После ревью стенда исправлены два P2. Проверка Referer разрешает у шрифта
только URL успешно загруженного stylesheet, действительно объявляющего этот
шрифт в CSSOM. У документа/CSS/JS/probe прежнее требование отсутствия Referer
сохраняется; в наблюдениях любого запроса запрещены bearer и token-страницы.
Это учитывает [правила CSS Referrer Policy](https://w3c.github.io/webappsec-referrer-policy/#integration-with-css).
Производственные заголовки не менялись. На этом шаге реальный Chromium ещё не запускался.

ManagedProcess отслеживает созданную группу после выхода лидера; TERM имеет
ограниченный срок, затем KILL и проверка отсутствия исполняющихся участников
по Linux /proc. Зомби не держат FD/порт, их сбор — задача init runner.
После наблюдённого исчезновения группа больше не используется для сигналов.
Это граница retirement: смена принадлежности числового PGID между проверками
не исключена и этим кодом не обнаруживается. Гарантия стабильной принадлежности
группы в таком интервале не заявляется; более сильный механизм не реализован. Если TERM
превысил срок, факт принудительного завершения не выдаётся за штатную остановку.
Общий abortResources исполняет все задачи очистки и возвращает ошибку, а abort
сохраняет её для финального cleanup; ошибки не теряются в allSettled.

Три новых проверки создают реального потомка в группе лидера, с loopback-портом
и обработчиком, игнорирующим SIGTERM: лидер заранее вышел, вышел по TERM,
либо очистка идёт через тот же abortResources, что у стенда. Подтверждены
прекращение исполнения потомка и повторное занятие освобождённого порта.
Независимая страховка теста убирает группу даже при прогоне старого кода/мутации.

Новые шесть мутаций: старое строгое условие Referer, снятие CSS whitelist,
запрета bearer, восстановление зависимости signal от живого лидера, пропуск
ожидания группы и игнорирование ошибок очистки. Все дали testCodeFailure.
Прежний ManagedProcess с текущими тестами воспроизводит ошибку; прежнее CSS-
условие воспроизведено семантически, без заявления о запуске Chromium.
Все подмены — во временных копиях. Девять прежних мутаций не повторялись,
их журналы сохранены как исторические. Результаты не являются браузерными тестами.

Логи, точный патч, baseline/candidate, manifest и проверка прежних jobs/30 файлов
A — test-results/auth-a-integration. Пакеты прежнего A и плана сохранены отдельно.
Сырые bearer, HTML/cookies/HAR/trace и stdout Next в артефакты не выгружаются.
Ошибки сценариев санитизируются; проверки точности сравнивают значения в памяти.

## Первый CI и исправления, 2026-10-29

Владелец передал логи после подготовки dev 4d4bbc4; Actions/API самостоятельно
не читались. Из 20 standalone/PG/HTTPS/Chromium-сценариев прошли 18. Среди них
браузерные формы/Referer, ограничения consume/reset, autoload и committed prepared,
доставка через collector, restart/crash/TERM. Два неверных ключа упали по ожиданию
выхода процесса; общий job красный. Это сведения владельца, не собственный прогон.

Причина по установленному Next: prepare вызывается заранее с catch/log;
ошибка instrumentation не гарантирует немедленный exit listener. План требует
отказ готовности, а не обязательное завершение процесса. Рабочий auth-код
не менялся. Стенд теперь требует ожидаемую диагностику ключа и HTTP 500 либо
диагностированный ненулевой exit. HTTP 200, посторонний 503, таймаут/обрыв,
permission error или отсутствие диагностики не являются успехом. При неверном
ключе искусственная операция остаётся pending, collector не получает писем.

В Docker-логе миграции выполнились дважды и роль gf_hub создана, но ожидание
таблиц осталось от старой схемы. Workflow теперь ожидает все 13 таблиц; тест
PGlite сравнивает этот список с результатом действительных миграций.

| Проверка исправлений | Собственный локальный результат |
|---|---|
| Harness, в том числе живые listener/exit и отрицательные контроли | 28/28 |
| db.pgtest.ts, в том числе точное ожидание Docker | 13/13 |
| Root tsc | exit 0 |
| Подмены во временных копиях | 8 целевых testCodeFailure |

Два replay воспроизводят прежнее ожидание exit и прежние семь таблиц; шесть
подмен ослабляют готовность/HTTP status/диагностику/сетевой отказ/permission/exit.
Первый sandbox-прогон harness с EPERM не засчитан; повтор вне sandbox прошёл.
Логи и точный fixes-срез — test-results/auth-ci-fixes. Старые пакеты не переписаны.
