## Запуск пользователем с доступом к тестовому Engine

Рабочая копия проекта, **fish**, Node >= 22.18 и локальный Docker Engine с BuildKit.
2026-10-23: прежний блок Bash заменён нативным скриптом fish по замечанию владельца.
Подготовленный скрипт — test-results/mail-image/build/run-local.fish; он запускается
отдельным процессом fish без пользовательского startup-конфига. Ошибка завершает
только скрипт, не интерактивную оболочку владельца. Агент проверил только синтаксис
через fish --no-execute; последующий результат запуска владельцем приведён выше.
Он использует отдельный пустой Docker config и явный локальный сокет,
создаёт только тестовый образ, запускает согласованный smoke с искусственными
ключами и без сети/опубликованных портов. Публикации и обновления сервисов нет.
Имя образа намеренно не совпадает с именами продовых образов.

Из корня проекта, в fish, пользователь с доступом к тестовому Engine:

```fish
fish --no-config test-results/mail-image/build/run-local.fish
```

Если endpoint недоступен и владельцу, сначала потребуется отдельно определить
тестовую среду с Engine. Не подменять адрес удалённым продовым Docker и не менять
права сокета/состав групп автоматически.

После успешного запуска записаны настоящий image ID и исход проверки
metadata/layout, HostConfig, четырёх отказов конфигурации, HTTP 401 и cleanup.
При ошибке остановиться и показать её перед дальнейшими правками. Digest GHCR
до отдельной публикации не существует; локальный image ID его не заменяет.
