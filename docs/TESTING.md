# Тесты и план проверок

## Как гонять

```bash
pnpm typecheck    # tsc: ядро и тесты; отдельно SDK с --checkJs
pnpm test         # юнит: node --test, ~1 с
pnpm test:db      # база на PGlite, без Docker; пик памяти ~1,3 ГБ (П-043)
pnpm test:e2e     # браузер: Chromium через Playwright, ~30 с; нужны games:build, games:export, hub:build
pnpm check        # всё по порядку, как в CI
```

**Где что гоняется (D-049).** На сервере - `typecheck`, `test`, сборка и экспорт игр во
временный `GF_DATA_DIR`, `gf check-prod`; `test:db` - только при свободной памяти ≥ 2 ГБ.
`hub:build` и e2e - только CI на пуше в `dev`: модуль, который импортирует хаб, может пройти
юнит и упасть в `next build` (П-045). Команды целиком - `CLAUDE.md`, раздел "Команды".

Один файл или один тест:

```bash
node --test apps/play-server/test/server.test.ts
node --test --test-name-pattern="обход пути" apps/play-server/test/server.test.ts
```

## Эталонный хаб

`tests/e2e/fixtures/mock-hub.html` - минимальный хаб: тот же iframe и тот же мост
(`packages/hub-bridge`, TS отдаётся браузеру через `module.stripTypeScriptTypes`).
Остаётся тестом протокола и подделок сообщений; игровые сценарии гоняются на настоящем
хабе (`hub.test.ts`), который e2e поднимает из сборки `pnpm hub:build`.

## Правило негативных тестов: проверка мутацией

Тест защиты должен **краснеть**, если защиту убрать. Иначе он доказывает только, что
код запускается. Порядок:

1. Скопировать файл с защитой во временную папку.
2. Снять защиту (удалить проверку, ослабить заголовок) и **проверить, что правка легла**
   (`grep`) - см. П-016.
3. Прогнать один тест: он обязан упасть.
4. Вернуть файл из копии и сверить побайтно (`cmp`).

## Чего тесты не покрывают (честно)

- Другие браузеры: e2e только в Chromium.
- Реальные домены и HTTPS: тесты идут на `*.localhost` по HTTP; прод проверялся руками
  (`curl`, `openssl`) при приёмке деплоя - итоги в истории STATE, автоматической проверки нет.
- Нагрузку моста (лимит 20/с проверен юнитом, поведение хаба под потоком запросов - нет);
  лимит мост держит в браузере игрока - серверные лимиты API этапа 1 отдельно (слайс 1.3).
- Режим разработки хаба (`next dev`) и игр (`vite`) - только сборки; dev-сервер e2e не гоняет.
- Образы Docker в CI собираются, а из контейнеров запускаются только `games`, `db`, `migrate`
  и зонд сети (`docker.yml`); хаб и сервер игр в контейнере e2e не гоняются.
- Восстановление базы из бэкапа проверено на пустой схеме - с данными повторить в слайсе 1.3.
