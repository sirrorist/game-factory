# Проектное сравнение интерфейса

Общий dev-инструмент сайта Game Factory и игр из `games/*/game.json`.
Все команды запускаются из корня репозитория. Нужны установленные workspace-зависимости,
Node ≥22.18 и Chromium (`pnpm exec playwright install chromium`).

```bash
pnpm ui:list
pnpm ui:baseline hub --ref HEAD --run header
pnpm ui:preview hub --run header
```

Последняя команда собирает рабочую версию и открывает две колонки до/после.
Для игры заменить `hub` её id, например `superwalk`, `snake` или `rogue-destiny`.
Любая игра с toolchain `static` или `vite-ts` подключается по манифесту без правки CLI.

## Обычный цикл

1. **До изменений** создать базу из конкретного commit: `ui:baseline <цель> --ref COMMIT --run имя`.
2. Внести изменения. `ui:preview <цель> --run имя` пересобирает «после» для ручной оценки.
3. `ui:check <цель> --run имя` собирает «после», выполняет матрицу и сохраняет снимки/отчёт.
4. `ui:compare <цель> --run имя` открывает готовые сборки и результаты без пересборки.
5. `ui:verify <цель> --run имя` проверяет просмотрщик; для Superwalk есть дополнительные
   проверки повторяемости и file:// через SW_UI_OFFLINE.
6. `ui:live <цель> --run имя` запускает живые сценарии адаптера, если они заданы.

Снимки из git собираются установленными зависимостями worktree; старый commit должен
быть совместим с текущим toolchain. База не перезаписывается, даже если её создание было прервано. Для следующей задачи
использовать новое имя `--run`; одинаковое имя указывать во всех командах этого сравнения.
Без `--run` используются ранее созданные сравнения `test-results/ui/<цель>/`.
Именованные проходы — `test-results/ui/<цель>/runs/<имя>/`.

Перед заменой «после» прежние сборка, отчёты, PNG и live-артефакты перемещаются в
`history/`. Новая сборка публикуется из чистого временного каталога: удалённые ресурсы
не остаются от предыдущей. Старый зелёный отчёт не подтверждает новый HTML или инструмент.
Незавершённая проверка сохраняет неполный статус и уже собранные доказательства.

## Просмотр

По умолчанию сайт открывается на `http://127.0.0.1:4183`, игра — на
`http://127.0.0.1:4179`. Другой порт: `--port 4190` или GF_UI_PORT.
Две версии получают отдельные локальные origins и localStorage, порты выбираются свободные.
Серверы работают до Ctrl+C; перед повторным запуском на том же порту остановить прежний.

Доступны одинаковый экран, размер, «до / после / обе», 100% и вписывание в колонку.
Масштаб меняет только предпросмотр, а выбранный viewport внутри iframe сохраняется.
Сайт дополнительно имеет выбор темы. Снимки становятся доступны только при актуальном
завершённом отчёте. Ненулевой пиксельный diff требует оценки, сам по себе это не ошибка.

Общие профили: 390×844, 844×390, 768×1024, 1024×768, Full HD, QHD и 4K.
Автоматика первых четырёх использует настоящую эмуляцию hasTouch/isMobile;
ручной iframe сам по себе не превращает ПК в телефон. Проверяется Chromium,
физические устройства и другие браузеры принимаются отдельно.

## Адаптеры

- [Хаб](targets/hub/README.md): реальные страницы и компоненты с явными образцами данных,
  две темы, формы/ошибки, fullscreen. Настоящий вход, API и игра внутри iframe исключены.
- [Superwalk](targets/superwalk/README.md): 23 сценария, live, кошелёк и границы адаптива.
- Остальные игры: штатные сборки, стартовый экран в семи профилях, ready(), ошибки,
  границы поля, полные PNG, PNG без canvas и пиксельный diff. Это не проверка прохождения.

Для редких состояний создать `targets/<id>/adapter.ts`, экспортирующий default UiAdapter
из [core/types.ts](core/types.ts). CLI находит его автоматически. Контракт: buildSnapshot
и comparison обязательны; check/live/verify и дополнительные commands опциональны.
Общие пути, профили, сборка игры, evidence, сервер и diff берутся из `core/`.
Инструментализация допускается только во временной копии сборки адаптера.
Обычные `src/`, dist, экспорт, SDK и протокол хаба ради сравнения не меняются.

Сценарии своей игры можно менять в её `targets/<id>/`; общий core/CLI — проектная задача.
Неизвестные размеры/состояния явно помечать непроверенными. Перед сдачей UI требуется
независимый просмотр по [REVIEWERS.md](REVIEWERS.md), а не только нули в JSON.

## Только dev

Сравнение **не запускается** командами `play`, `hub`, `hub:start`, `hub:build`,
`games:build`/`games:export` и production compose. Импортов из приложений нет;
весь `tests/` уже исключён из Docker-контекста через `.dockerignore`.
Сервер слушает только `127.0.0.1`, явный запуск с NODE_ENV=production запрещён.
Новые прод-сервисы, маршруты, порты и автозапуск не добавляются.

```bash
pnpm ui:typecheck
pnpm ui:test
```

Тесты проверяют неизменность базы, историю после пересборки, обнаружение подмены HTML,
раздельные origins, пути/симлинки, экранирование метаданных, неполные отчёты и запрет
production-запуска. Старые документы с командами `games/superwalk/ui/...` описывают
исторические прогоны; исполняемые файлы перенесены сюда. Прежние доказательства сохранены.

Проверка переноса на трёх готовых целях: `pnpm ui:smoke`. Она использует текущие
сравнения hub/superwalk и отдельный проход snake с именем project-tool; эти базы
и after должны быть заранее подготовлены. Обычная проверка произвольной цели — ui:verify.
