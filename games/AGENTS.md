# Игры - правила агента

> Действует для любого агента, который правит `games/`. Подробно, с командами и образцами, -
> [`../docs/GAME-AGENTS.md`](../docs/GAME-AGENTS.md); что требовать и как сдавать - шаблон ТЗ
> [`../docs/GAME-TZ.md`](../docs/GAME-TZ.md). Прочитать оба **до** первой правки, затем
> `games/<id>/DESIGN.md` (ТЗ игры) и `games/<id>/NOTES.md`.

## Главное

- **Одна сессия - одна игра.** Правишь `games/<id>/` своей игры; её UI-сценарии — в `tests/ui/targets/<id>/`. Нужна правка SDK, моста,
  шаблона, сервера игр, CI - не делаешь, а пишешь вопрос владельцу в `games/<id>/NOTES.md`.
- **Без брифа не начинать.** Бриф и критерии "готово, когда" - первым разделом `NOTES.md`
  (образец - `docs/GAME-AGENTS.md`, раздел 3). Нет критерия - спроси владельца.
- **Память - `games/<id>/NOTES.md`**: бриф, состояние, решения, дальше. Начало сессии - прочитать,
  конец - переписать. Чат забудется, файл - нет.
- **Шаг - одна функция игры**, после каждого шага проверки зелёные. Логика - чистыми функциями
  с тестами `games/<id>/test/*.test.ts`, отрисовка - отдельно.
- **Готово - это команды**, а не слова: список "Готово" в `docs/GAME-AGENTS.md`, раздел 6. Чего
  не проверил (телефон, браузер глазами) - так и пишешь.
- **Галочка - только с доказательством**: тест, скриншот или строка F3 по таблице приёмки ТЗ.
  "Исправлено" без доказательства - не исправлено (урок `rogue-destiny`, `docs/GAME-TZ.md`).
- **Интерфейс — отдельная проверка**: автоматический прогон, сравнение до/после владельцем
  и независимая проверка агентами. Все старые и новые экраны проверяются на телефоне
  390×844 / 844×390, планшете 768×1024 / 1024×768, Full HD 1920×1080,
  QHD 2560×1440 и 4K 3840×2160. Базу фиксировать до правок, не заменять ради зелёного
  результата. `pnpm shots` с тремя снимками не заменяет эту приёмку. Реализация и шаблоны
  заданий проверяющим — [`../tests/ui/README.md`](../tests/ui/README.md) и
  [`../tests/ui/REVIEWERS.md`](../tests/ui/REVIEWERS.md); другим играм адаптировать сценарии.
- **Телефон = ПК**, движение через `dt`, бюджет оптимизации - обязательные требования
  `docs/GAME-TZ.md`, даже если в ТЗ игры о них ни слова.
- Факт в отчёте - с источником: **проверено** (команда и итог) / **со слов владельца** /
  **предположение**.

## Устройство игры - коротко

- `game.json` - манифест (GAMES.md, "Поля манифеста"); `id` = поддомен; опубликованный `version`
  неизменяем - правка игры = новый `version`.
- SDK: `const gf = await GameFactory.init({ gameId })`, `save` / `load` (JSON до 64 КБ),
  `submitScore` / `bestScore`, `gf.ready()` - когда игра правда готова к вводу (SDK.md).
- Офлайн-архив открывают через `file://`: без `fetch`/XHR за ассетами (картинки - импортом или
  кодом), без top-level `await` (весь запуск - в `async function main()`).
- TypeScript: относительные импорты с `.ts`, `import type` для типов, без `enum` и `namespace`.
- Комментарии и тексты игры - по-русски.

## Нельзя

- `commit`, `push`, `merge`, новые ветки - только по "да" владельца.
- STATE, ROADMAP, DECISIONS, CHANGELOG, PITFALLS - их ведёт сессия на сервере.
- Чужие ассеты, бренды и названия игр. Графика - своя (кодом или своими файлами).
- Обходить песочницу: игра - недоверенный код, её ограничения - защита платформы, а не баг.
- Читать `.env`, ключи и `deploy/secrets/`.
