# Superwalk: проверка интерфейса

Общие правила: `../AGENTS.md`, `../../docs/GAME-AGENTS.md`, `../../docs/GAME-TZ.md`.
Перед правками прочитать `DESIGN.md`, `NOTES.md`, `MISTAKES.md` и `PITFALLS.md`.

Текущий порядок работы задан владельцем в `UI-REVISION-PLAN.md`: реализация и его
приёмка по каждому пункту 1–6, затем общий автоматический прогон и независимый просмотр
в пункте 7. После пункта 1 владелец уточнил: изменения → сборка предпросмотра → его
приёмка; браузерные прогоны, снимки и подробные проверки только в пункте 7. Не объявлять полный
UI-прогон состоявшимся. Это указание владельца уточняет правила проверки ниже.

- Любая правка интерфейса и любой новый элемент проходят отдельный UI-прогон:
  `pnpm ui:check superwalk`. Юнит-тесты его не заменяют.
  Анимации/скролл/фокус отдельно: `pnpm ui:live superwalk` с тем же hash after, complete:true и failed:0.
  В игре Tab сохраняет открытие обзора при удержании; кошелёк изолирует Tab/Shift+Tab.
- До первой правки сохранить исходную версию: `pnpm ui:baseline superwalk --ref HEAD --run имя`.
  Базу не обновлять ради зелёной проверки. В отчёте фиксировать её commit и версию.
- Обязательные профили: телефон 390×844 и 844×390; планшет 768×1024 и 1024×768;
  Full HD 1920×1080; 2K (QHD) 2560×1440; 4K 3840×2160. Тач проверяется отдельно
  от ширины окна; iframe на ПК сам по себе не эмулирует телефон.
- Матрица включает все прежние экраны и состояния. Для нового элемента дополнить
  `tests/ui/targets/superwalk/config.ts` и сценарий в `tests/ui/targets/superwalk/fixtures.ts`; проверка только нового экрана недостаточна.
- Проверять ошибки браузера, выход за экран, достижимость кнопок внутри прокрутки,
  перекрытия HUD, цели касания ≥ 48 px, переходы между окнами и рабочие действия.
- Перед сдачей открыть `pnpm ui:compare superwalk`: две версии, одинаковый экран и размер;
  сохранить полные снимки, снимки только UI и `report.json`. Пиксельные отличия требуют
  объяснения, а не автоматической замены базы; анимации проверяются отдельно.
- Независимым проверяющим дать шаблоны из `tests/ui/REVIEWERS.md` и реальные артефакты.
  Их отчёт проверять по указанным координатам/снимкам перед исправлением.
- «Проверено» означает состоявшийся прогон с результатом. Эмулятор Chromium,
  реальный телефон, Safari и оценка владельца — разные проверки; ограничения писать явно.
- Коммит, push и обновление базы — только по отдельному указанию владельца.

Команды и границы сравнения: [проектный инструмент](../../tests/ui/README.md). Результаты — в `NOTES.md`.
