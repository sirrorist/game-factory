## Грабли Three.js: Координаты, инверсия клавиш A/D (влево/вправо) и камеры от 3-го лица

### Симптом
- При нажатии **A** персонаж смещается **вправо** по экрану, а при **D** — **влево** по экрану (инвертировано управление).
- При движении вперёд персонаж бежит спиной вперед, либо при повороте мыши персонаж двигается в обратную сторону.
- Ранее эта же грабля возникала в игре `rogue-destiny` (коммит `456938b` / строка `tempMoveDir.x += 1` при `keys.left`).

### Причина
В правосторонней декартовой системе координат Three.js:
- Ось **+X** направлена **вправо**
- Ось **+Y** направлена **вверх**
- Ось **+Z** направлена **к зрителю / из экрана**
- Ось **-Z** направлена **вглубь экрана / от зрителя**

Когда камера находится в стандартном положении от 3-го лица (за спиной героя и смотрит вперед вглубь экрана):
- Камера находится на оси **+Z** относительно героя: `cz = pz + Math.cos(yaw) * camDist` (при `yaw = 0` координата камеры `cz = pz + camDist`).
- Камера направлена в сторону **-Z** (`camera.lookAt(px, py, pz)`).
- При взгляде в направлении **-Z**:
  - Экранное **право** — это **+X** (клавиша **D**, `strafe = 1`).
  - Экранное **лево** — это **-X** (клавиша **A**, `strafe = -1`).
  - Экранный **вперёд** (вглубь сцены) — это **-Z** (клавиша **W**, `forward = 1`).
  - Экранный **назад** (к зрителю) — это **+Z** (клавиша **S**, `forward = -1`).

Если ошибочно задать положение камеры через `- Math.cos(yaw) * camDist`:
Камера оказывается спереди от героя на **-Z** и смотрит на героя в сторону **+Z**.
Но при взгляде в сторону **+Z** ось **+X** находится **слева**, а ось **-X** — **справа**!
В результате положительное смещение `+X` (от клавиши D) смещает персонажа влево по экрану, а `-X` (от клавиши A) — вправо по экрану!

### Железное правило расчёта для 3D от 3-го лица

#### 1. Позиционирование камеры (следит за героем сзади)
```ts
const camDist = 6.2;
const cx = player.x + Math.sin(yaw) * Math.cos(pitch) * camDist;
const cz = player.z + Math.cos(yaw) * Math.cos(pitch) * camDist;
const cy = player.y + 1.3 + Math.sin(pitch) * camDist;
camera.position.set(cx, cy, cz);
camera.lookAt(player.x, player.y + 1.0, player.z);
```

#### 2. Вектор перемещения героя в мире (с учетом поворота камеры yaw)
```ts
// yaw = 0: W -> -Z (вглубь), S -> +Z (к камере), D -> +X (вправо), A -> -X (влево)
const sin = Math.sin(yaw);
const cos = Math.cos(yaw);

const moveX = (-forward * sin + strafe * cos) * speed;
const moveZ = (-forward * cos - strafe * sin) * speed;

nextX = currentX + moveX * dt;
nextZ = currentZ + moveZ * dt;
```

#### 3. Ориентация 3D-модели героя
- При базовом угле `rotation.y = 0` модель должна смотреть мордочкой в **-Z** (нос на `-Z`, хвост на `+Z`).
- В Three.js поворот вокруг оси +Y на угол $\theta$ переводит локальный вектор $(0, 0, -1)$ в $(-\sin\theta, 0, -\cos\theta)$.
- Чтобы модель смотрела вдоль вектора движения $(moveX, moveZ)$, требуется:
  $-\sin\theta = moveX \implies \sin\theta = -moveX$
  $-\cos\theta = moveZ \implies \cos\theta = -moveZ$
- Поэтому целевой угол поворота модели вычисляется строго как:
```ts
const targetAngle = Math.atan2(-moveX, -moveZ);
```
- Проверка углов:
  - Бег вперед (`moveX = 0, moveZ < 0`): `Math.atan2(0, positive) = 0` (лицом вперед в -Z).
  - Бег назад (`moveX = 0, moveZ > 0`): `Math.atan2(0, negative) = PI` (лицом к камере в +Z).
  - Бег вправо (`moveX > 0, moveZ = 0`): `Math.atan2(-positive, 0) = -PI/2` (поворот направо в +X).
  - Бег влево (`moveX < 0, moveZ = 0`): `Math.atan2(positive, 0) = +PI/2` (поворот налево в -X).

#### 4. Обзор мышью
- Движение мыши вправо (`movementX > 0`): `yaw -= movementX * sens` (орбитальная камера облетает героя, поворачивая обзор направо).
- Движение мыши вверх (`movementY < 0`): `pitch` уменьшается (камера опускается ниже).
- Движение мыши вниз (`movementY > 0`): `pitch` увеличивается (камера поднимается выше).

## Грабли ADB: Подключение телефона по Wi-Fi (Android 11+)

### Симптом
При попытке подключить телефон через `adb connect <IP>:<PORT>` консоль выдаёт:
`error: protocol fault (couldn't read status message): No error`

### Причина
В Android 11+ в "Беспроводной отладке" есть **два разных порта**:
1. **Порт сопряжения (Pairing Port)**: отображается во всплывающем окне «Подключить с помощью кода сопряжения» (например, `<IP>:37891`). Этот порт предназначен **только** для команды `adb pair`. Он работает по TLS/SPAKE2, а не по стандартному протоколу ADB. Если вызвать `adb connect` на этот порт — сервер сразу разрывает соединение с ошибкой `protocol fault: No error`.
2. **Порт подключения (Connect Port)**: отображается на **главном экране** «Беспроводная отладка» в строке «IP-адрес и порт» (например, `<IP>:43215`).

### Правильная последовательность сопряжения по Wi-Fi
1. Открыть окно «Подключить с кодом сопряжения» на телефоне.
2. Ввести в терминале сопряжение:
   ```powershell
   adb pair <IP>:<ПОРТ_ИЗ_ОКНА_СОПРЯЖЕНИЯ> <6-ЗНАЧНЫЙ_КОД>
   # Пример: adb pair 192.0.2.50:37891 123456
   ```
3. Закрыть окно сопряжения на телефоне.
4. Ввести подключение, используя порт с **главного экрана**:
   ```powershell
   adb connect <IP>:<ПОРТ_С_ГЛАВНОГО_ЭКРАНА>
   # Пример: adb connect 192.0.2.50:43215
   ```
5. Пробросить порт хаба:
   ```powershell
   adb reverse tcp:4100 tcp:4100
   ```
6. Открыть `http://localhost:4100` в Chrome на телефоне.

### Еще более простой вариант (без Wi-Fi pairing):
- Подключить телефон **по USB-кабелю**, разрешить отладку и выполнить:
  ```powershell
  adb reverse tcp:4100 tcp:4100
  ```
  И сразу открыть `http://localhost:4100` на телефоне.
- Либо без ADB вообще (если телефон и ПК в одной Wi-Fi сети): открыть в браузере телефона `http://<IP_компьютера_в_сети>:4100`.
