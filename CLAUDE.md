# Game Factory - правила агента для этого проекта

> Общие правила (канарейка, секреты, что требует прямого "да", формат команд для человека)
> приезжают из `global-agent-kit` и действуют здесь целиком. Этот файл их **уточняет**,
> а не заменяет. Новое общее правило - в кит, а не сюда.

## Начало сессии - поднять контекст из файлов

1. [`docs/STATE.md`](docs/STATE.md) - где остановились, что проверено, что блокирует.
2. [`docs/ROADMAP.md`](docs/ROADMAP.md) - текущий этап и его критерии готовности.
3. По задаче: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/SECURITY.md`](docs/SECURITY.md),
   [`docs/PITFALLS.md`](docs/PITFALLS.md) - **до** правки, а не после.
4. Прогнать `pnpm check` и сверить с тем, что записано в STATE. Расхождение - первая находка.

## Конец сессии - зафиксировать состояние в файлы

- `docs/STATE.md` - что сделано, что проверено **и чем** (команда + итог), что не проверено,
  следующий шаг, открытые вопросы. Переписывается, а не дописывается хвостом.
- `docs/DECISIONS.md` - каждое решение, принятое в сессии: что выбрали, почему, что отвергли.
- `docs/PITFALLS.md` - каждая грабля, на которую наступили: симптом, причина, как обходить.
- `docs/GAMES.md` - если менялся состав игр.

Сессия без обновлённого STATE не закончена: следующий агент начнёт с неправды.

Факт о внешнем мире (прод, GitHub, DNS, сервер) - "проверено" только с командой и её итогом.
Облачная сессия не видит сервер, сессия на VPS-1 - Docker: чего не видишь, то "предположение"
или "со слов владельца", даже если это записано в прошлом STATE.

## Где работает агент

- **Облачная сессия** - код и документы; Docker там есть (П-025…П-027).
- **Сессия на VPS-1** - сервер. Там **нет `root` и нет Docker** (П-036): всё, что трогает
  прод, - блоком команд для владельца. Прод-конфиг - копии root (D-035); как с ним
  работать - `docs/OPERATIONS.md`.
- Проект описан и в приватной базе инфраструктуры (путь знает сессия на VPS-1).
  Меняется адрес, домен, Traefik, память, бэкап - обновить и там.
- **Репозиторий публичный.** О сервере здесь - только веб-адрес, домены и файлы `deploy/`;
  чего не писать - D-043. Перед коммитом документов - проверка по его списку.

## Проект в двух строках

Хаб браузерных игр. Каждая игра - пакет с `game.json`, публикуется неизменяемой версией
и отдаётся со своего поддомена `<id>.play.<домен>`, хаб встраивает её в iframe и общается
через SDK по `postMessage`. Всё, что пришло из игры, - недоверенный ввод.

## Язык и код

- **TypeScript**, исполняется Node напрямую (type stripping, Node ≥ 22.18). Отсюда:
  - только стираемый синтаксис: без `enum`, `namespace`, parameter properties
    (`erasableSyntaxOnly` в tsconfig это ловит);
  - относительные импорты - с расширением `.ts`;
  - `import type` для типов (`verbatimModuleSyntax`).
- **Ядро без зависимостей**: `apps/play-server`, `tools/`, `packages/manifest`,
  `packages/registry`, `packages/game-sdk`, `packages/hub-bridge` используют только
  стандартную библиотеку Node. Зависимость в ядро - только через запись в DECISIONS.
- SDK игр - **классический скрипт** (`gf-sdk.js`) с JSDoc-типами и `index.d.ts`,
  проверяется `tsc --checkJs`. Не переписывать в ESM: сломается `file://` (PITFALLS).
- Комментарии и сообщения об ошибках - по-русски, по делу: *почему*, а не *что*.
- Тесты - `node:test` + `node:assert/strict`; браузер - `playwright`.

## Инварианты - нарушение ломает безопасность

1. Игра отдаётся **только со своего поддомена**; служебный хост игр не отдаёт файлы игр.
2. Опубликованная версия **неизменяема**: другое содержимое - другой `version`.
3. Мост хаба принимает сообщение, только если совпали **и** `event.source`, **и** `event.origin`.
4. `postMessage` из хаба в игру - всегда с точным origin игры, никогда `"*"`.
5. Защитные заголовки сервера игр меняются вместе с `docs/SECURITY.md` и тестами.
6. Негативный тест песочницы, который не краснеет при снятой защите, - не тест
   (проверка мутацией, см. `docs/TESTING.md`).

## Команды

`pnpm check` - полный прогон, как в CI. Остальные - в [`README.md`](README.md).

## Коммиты и ветки

- Коммит, пуш, создание веток - только после прямого "да" владельца (правило кита).
- Ветки (D-042): работа - в `dev`; `main` - прод (пуш в `main` = выкладка). В `main` -
  только перемоткой `dev` и отдельным "да". **Новых веток не создавать** без разрешения
  владельца - и ту `claude/…`, которую просит облачная среда, тоже.
- Сообщение коммита - по-русски, заканчивается сутью изменений; трейлеров нет.
- Один коммит на сессию, если не договорились иначе.
