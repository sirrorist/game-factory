# Game Factory - правила агента для этого проекта

> Общие правила (канарейка, секреты, что требует прямого "да", формат команд для человека)
> приезжают из `global-agent-kit` и действуют здесь целиком. Этот файл их **уточняет**,
> а не заменяет. Новое общее правило - в кит, а не сюда.

## Начало и конец сессии - навыками

- **Начало - навык `session-start`** (`.claude/skills/session-start/SKILL.md`): `git fetch` и
  сверка `dev` с `origin/dev` (П-041), снимок STATE, задача этапа из ROADMAP и `docs/specs/`,
  грабли по теме, локальная проверка против чисел в STATE. Расхождение - первая находка.
- **Конец - навык `handover`** (`.claude/skills/handover/SKILL.md`): запись в
  `docs/CHANGELOG.md` (сделано, проверено **и чем**), STATE переписан снимком ≤ 120 строк
  (D-052), DECISIONS, PITFALLS (в раздел по теме, следующим номером), TESTING, SECURITY,
  ROADMAP-факт (статус пункта и этапа меняет только владелец), проверки, коммит с "да".
- Карта всех документов - [`docs/README.md`](docs/README.md). По задаче
  [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md), [`docs/SECURITY.md`](docs/SECURITY.md),
  [`docs/PITFALLS.md`](docs/PITFALLS.md) - **до** правки, а не после.

Сессия без обновлённого STATE не закончена: следующий агент начнёт с неправды.

Факт о внешнем мире (прод, GitHub, DNS, сервер) - "проверено" только с командой и её итогом.
Сессия на VPS-1 не видит Docker: чего не видишь, то "предположение" или "со слов владельца",
даже если это записано в прошлом STATE.

## Где работает агент

- **Только сессия на VPS-1** (D-049): и код, и сервер. Облачных сессий больше нет.
- Работа - в рабочей копии ветки `dev`; копия `main` - только смотреть, что на проде (П-041).
- **Нет `root` и нет Docker** (П-036): всё, что трогает прод, - блоком команд для владельца.
  Прод-конфиг - копии root (D-035); как с ним работать - `docs/OPERATIONS.md`.
- **Что проверяется где** (D-049): на сервере - типы, юнит-тесты, сборка и экспорт игр,
  сверка с продом; сборка хаба и e2e - только CI на пуше в `dev` (памяти сервера на
  `next build` и Chromium рядом с продом не хватает). База для тестов - PGlite, не Docker.
- Проект описан и в приватной базе инфраструктуры (путь знает сессия на VPS-1).
  Меняется адрес, домен, Traefik, память, бэкап - обновить и там.
- **Репозиторий публичный.** О сервере здесь - только веб-адрес, домены и файлы `deploy/`;
  чего не писать - D-043. Адреса, пути и слова из списка ловит `tools/public-repo.test.ts`
  (D-053), остальное - глазами по списку перед коммитом.
- Чтение `.env`, `deploy/secrets/` и ключей агенту закрыто в `.claude/settings.json` (D-053);
  `cat` и `grep` по ним через Bash - тоже нельзя (правило кита о секретах).

## Проект в двух строках

Хаб браузерных игр. Каждая игра - пакет с `game.json`, публикуется неизменяемой версией
и отдаётся со своего поддомена `<id>.play.<домен>`, хаб встраивает её в iframe и общается
через SDK по `postMessage`. Всё, что пришло из игры, - недоверенный ввод.

## Язык и код

- **TypeScript**, исполняется Node напрямую (type stripping, Node ≥ 22.18). Отсюда:
  - только стираемый синтаксис: без `enum`, `namespace`, parameter properties
    (`erasableSyntaxOnly` в tsconfig это ловит);
  - относительные импорты - с расширением `.ts`;
  - `import type` для типов (`verbatimModuleSyntax`).
- **Ядро без зависимостей**: `apps/play-server`, `tools/`, `packages/manifest`,
  `packages/registry`, `packages/game-sdk`, `packages/hub-bridge` используют только
  стандартную библиотеку Node. Зависимость в ядро - только через запись в DECISIONS.
  Не ядро: `apps/hub` (Next.js), `packages/db` (Drizzle, D-051), `packages/vite-config`,
  шаблоны и игры.
- SDK игр - **классический скрипт** (`gf-sdk.js`) с JSDoc-типами и `index.d.ts`,
  проверяется `tsc --checkJs`. Не переписывать в ESM: сломается `file://` (PITFALLS).
- Комментарии и сообщения об ошибках - по-русски, по делу: *почему*, а не *что*.
- Тесты - `node:test` + `node:assert/strict`; браузер - `playwright`.

## Инварианты - нарушение ломает безопасность

1. Игра отдаётся **только со своего поддомена**; служебный хост игр не отдаёт файлы игр.
2. Опубликованная версия **неизменяема**: другое содержимое - другой `version`.
3. Мост хаба принимает сообщение, только если совпали **и** `event.source`, **и** `event.origin`.
4. `postMessage` из хаба в игру - всегда с точным origin игры, никогда `"*"`.
5. Защитные заголовки сервера игр меняются вместе с `docs/SECURITY.md` и тестами.
6. Негативный тест песочницы, который не краснеет при снятой защите, - не тест
   (проверка мутацией, см. `docs/TESTING.md`).

## Роль "Безопасность" - на каждый diff в опасной зоне

- Правка play-server, моста, SDK, `deploy/`, загрузки игр, авторизации - через сабагента
  `security` (`.claude/agents/security.md`, D-046): он читает diff и `docs/SECURITY.md`,
  ничего не меняет. Как звать и что он отдаёт - [`docs/ROLES.md`](docs/ROLES.md).
- Отчёт роли - заявка, а не итог: каждую находку открыть по адресу, прежде чем чинить.
- Модель - Sonnet 5.5 / `high` из фронтматтера; какая работала на деле - по полю `model` в
  журнале запуска, не по файлу (П-042).

## Команды

Локально на сервере (D-049), игры - во временный каталог данных, не в `.data` рабочей копии:

```
pnpm typecheck && pnpm test
GF_DATA_DIR=<временный каталог> pnpm games:build && GF_DATA_DIR=<тот же> pnpm games:export
pnpm test:db      # PGlite, пик ~1,3 ГБ - только при свободной памяти ≥ 2 ГБ (П-043)
GF_DATA_DIR=<тот же> GF_PROD_GAME_URL='https://{id}.play.youranus.ru/' pnpm gf check-prod
```

`pnpm check` - полный прогон, как в CI (с `hub:build` и e2e); на сервере не гонять.
Остальные - в [`README.md`](README.md), подробно про тесты - [`docs/TESTING.md`](docs/TESTING.md).

## Коммиты и ветки

- Коммит, пуш, создание веток - только после прямого "да" владельца (правило кита).
  Пуш в `dev` и `main` сторож агенту не даёт - пуш отдаётся владельцу блоком.
- Ветки (D-042): работа - в `dev`; `main` - прод (пуш в `main` = выкладка). В `main` -
  только перемоткой `dev` и отдельным "да". **Новых веток не создавать** без разрешения
  владельца.
- Сообщение коммита - по-русски, заканчивается сутью изменений; трейлеров нет.
- Один коммит на сессию, если не договорились иначе.
